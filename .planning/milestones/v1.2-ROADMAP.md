# Milestone v1.2: Quote-to-Customer

**Status:** ✅ SHIPPED 2026-05-25
**Phases:** 12–17 (7 phases, includes inserted 15.1 + closure 17)
**Total Plans:** 45
**Requirements:** 30 total — 28 satisfied, 2 withdrawn (TAGS-02 chip strip, DUP-01 row action)
**Defined:** 2026-05-20

## Overview

Turn 3DCoster from a personal cost calculator into a tool that produces professional, customer-ready quotes — with proper tax handling, customer details, an organized job library, and a real PDF deliverable. All work stayed on the FREE side of the free/paid line (no Supabase, no API calls, no backend).

**Constraints encoded in this roadmap:**

- All phases were FREE tier — no paid-tier work in this milestone
- All phases were LOCAL-ONLY — no backend, no Supabase, no API calls
- Phase 12 (schema) was foundational: every other phase depended on the Dexie v6 migration landing first
- Phase 16 (PDF) could not start until both Phase 13 (Tax) and Phase 14 (Customer) were merged — the PDF must render a complete tax row and customer block from day one
- `build.modulePreload: false` in `vite.config.ts` was mandatory before Phase 16 shipped — without it Vite generates `<link rel="modulepreload">` for the lazy PDF chunk and silently defeats the 300 KB gz budget win
- Tax applies to `sellingPrice`, not `subtotal` — the existing `it.todo` in `costCalc.test.ts` was the activation point and was the first thing activated in Phase 13

**Phase structure rationale (coarse granularity):**
The 25 original requirements clustered into five natural delivery boundaries driven by hard dependencies:

1. Schema migration unblocked all data fields — shipped alone to be testable before field consumers were written
2. Tax + UI sweep cohered because both touched CostCalculator and Settings forms — applying the `compact`/`InfoTooltip` sweep once while those files were open avoided double-touching them
3. Customer details + Etsy helper cohered because both added collapsible sections to the cost calculator screen — same file, same UI pattern, same one-time forms sweep for new fields
4. Tags + search + quick duplicate cohered because all three were JobsManager work (tag chip filter, search bar, and duplicate row action lived in the same component)
5. PDF was last by hard constraint — it assembled the tax row, customer block, and job data all built in phases 13–15

UI-08/09/10 all folded into Phase 13. Phase 15.1 was inserted mid-milestone (2026-05-22) when the Record Sale modal screamed for a real customer picker; Phase 17 was added (2026-05-25) as a closure phase after the milestone audit surfaced a Rollup chunk-ordering bug that defeated PDF-04 lazy-loading.

## Milestone Summary

**Key Decisions** (extracted from phase summaries):

- Three-layer tax model (region default → Settings → per-job override) — single coherent shape; no half-feature
- Tax applies to `sellingPrice` not `subtotal` — order-of-operations test in `costCalc.test.ts` activated as Phase 13's first gate
- Mid-UAT scope reversal in Phase 14: customer details moved from PrintJob → Sale (D-21); Etsy section conditional on `marketplace === 'etsy'` (D-22). User-approved at checkpoint.
- Customer Library is a separate Dexie store with **by-value sale snapshots** — editing a library record never mutates historical sales (locked by unit test)
- TAGS-02 chip filter withdrawn 2026-05-24 per user feedback (redundant with TAGS-03 substring search across tag names)
- DUP-01 row-action UI withdrawn-from-v1.2 per user feedback (single-item overflow is wrong pattern); `duplicateJob()` helper + 7-case Vitest contract LOCKED for v1.3+ consumers
- Edit-in-place tag editor (Phase 15 Gap E Round 2): inline chip strip with hover ✕ + narrow `+` add-tag input — replaces the dropped-down panel from Round 1
- PDF shipped as Quote interface with Dexie v7→v8 migration — `generateQuotePdf` takes a Quote arg; PrintQuoteModal transactionally writes the Quote + bumps `nextQuoteNumber`; Convert-to-Sale flow links Sale ↔ Quote
- PDF-04 lazy-load defeated by Rollup chunk ordering — fixed Phase 17 by reordering `manualChunks` predicate so `/src/pdf/` + `/jspdf/` matches BEFORE `node_modules` catch-all; new `scripts/assert-no-static-pdf-import.mjs` build-output CI gate prevents regression
