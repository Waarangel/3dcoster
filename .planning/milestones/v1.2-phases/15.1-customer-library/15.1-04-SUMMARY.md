# Phase 15.1 Plan 04: Record Sale Combobox + Auto-Link + Auto-Create Summary

The Record Sale modal now has a WAI-ARIA combobox picker above the existing 4-field Customer block (Phase 14 D-21). Picking a saved customer fills Name/Email/Company/Address without touching Notes (D-05) and bumps lastUsedAt (D-03). On Save sale without picking, if Name OR Email is non-empty, the sale either silently links to an email-matched library record (D-07) or auto-creates a new one (D-06). The per-Sale customer snapshot is byte-identical before and after the auto-link block — the by-value rule (D-05) holds, and CL-05's by-value invariant from Plan 01 is preserved.

## By-Value Snapshot Preservation (CL-05 invariant from Plan 01)

The `customer` payload constructed at `JobsManager.tsx:613–621` is **byte-identical** before and after the Plan 04 auto-link/auto-create block. No field of `customer` is reassigned after the block; the same `customer` object is passed to `addSale`/`updateSale`. The auto-link path bumps `lastUsedAt` on the **library** record via `bumpLastUsed(existing.id)` and explicitly does NOT call `updateCustomer(...)` — library fields stay as the user originally typed them, per D-07.

This preserves CL-05's by-value snapshot invariant (architecturally locked by the Vitest test at `src/utils/byValueSnapshot.test.ts` from Plan 01): editing or deleting a library Customer cannot mutate any historical Sale.customer snapshot.

### Additive (not auto-fixes — explicit design decisions documented for the verifier)

**1. `aria-selected={i === customerPickerActiveIndex}` added to each listbox option**
- **Not in PATTERNS.md §12d skeleton** — the skeleton omits `aria-selected` from the option
- **Rationale:** WAI-ARIA combobox spec requires `aria-selected` on `role="option"` rows to communicate active-state to assistive tech. The visual highlight (`bg-blue-500/10 text-blue-300`) needs an ARIA peer or screen-reader users get a degraded experience compared to sighted users using the same keyboard navigation.
- **No CONTEXT/UI-SPEC contradiction** — UI-SPEC §5 explicitly calls out "full WAI-ARIA combobox pattern" as a LOCKED requirement; `aria-selected` is part of that pattern.

**2. `onMouseEnter` on each option to sync `customerPickerActiveIndex` with hover**
- **Not in PATTERNS.md §12d skeleton** — but called out in the plan's Task 2 acceptance criteria as part of the locked combobox pattern (`aria-activedescendant` must follow the actively-focused row, and mouse hover should move that focus)
- **Rationale:** Without this, mouse-hover and keyboard-active diverge — confusing UX. Standard combobox pattern unifies them.
