# Phase 15.1 — UI Design Contract

> Visual and interaction contract for the Customer Library phase. Generated by gsd-ui-researcher; verified by gsd-ui-checker.

This phase ships three new component surfaces (`CustomerLibrary`, `CustomerEditModal`, `CustomerCsvImportModal`) plus a combobox grafted into the existing Record Sale modal and a new tab in main nav. **Every visual decision in this spec is bound to an existing precedent in the codebase** — AssetLibrary for the tab, CsvImportModal for the importer, JobsManager Record Sale for the picker host, and the shared `ui/*` primitives for everything else. The contract's job is to (a) confirm the inherited design tokens, (b) pin the discretion items CONTEXT.md left open, and (c) capture the copywriting executor needs to ship without ambiguity.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Tailwind utility-class system, no preset framework) |

**Architectural notes for the executor:**

- All shared UI primitives expose `btnSize`/`inputSize`/`selectSize`/`textareaSize` — never the HTML-conflicting `size` prop.
- Primitive imports come from the barrel: `import { Button, Input, EmptyState } from './ui';` (precedent: AssetLibrary.tsx:5).
- New components live at `src/components/CustomerLibrary.tsx`, `src/components/CustomerEditModal.tsx`, `src/components/CustomerCsvImportModal.tsx` per CONTEXT canonical_refs.

## Typography

The project uses Tailwind's default type ramp. Phase 15.1 uses **3 sizes** and **2 weights** — same set already shipping in AssetLibrary and CsvImportModal. No new type tokens.

| Role | Size | Tailwind | Weight | Tailwind | Line Height | Usage in this phase |
|------|------|----------|--------|----------|-------------|---------------------|
| Display / Section heading | 18px | `text-lg` | 600 (semibold) | `font-semibold` | 1.4 (Tailwind default for `lg`) | Modal headers ("Add customer" / "Edit customer" / "Import customers from CSV"), Customers tab page heading, EmptyState title |
| Body / Label | 14px | `text-sm` | 500 (medium) | `font-medium` | 1.4 (Tailwind default for `sm`) | Customer row name (line 1 — bold via `font-medium text-white`), form labels, button labels (`Button.tsx` `md`+`sm` use `text-sm`), tab labels |
| Body | 14px | `text-sm` | 400 (regular) | (default) | 1.4 | Form input values, modal body copy, search input |
| Muted secondary | 14px | `text-sm` | 400 (regular) | (default) | 1.4 | "email · company" subline (with `text-slate-400`), "Last used: ..." right-rail label, helper text |
| Caption / Meta | 12px | `text-xs` | 400 (regular) | (default) | 1.4 | Mobile tab labels, validation error inline copy in CSV preview, "Showing first 8 of 23" combobox footer |
| Tab nav label | 12px (mobile) / 14px (desktop) | `text-xs sm:text-sm` | 500 | `font-medium` | 1 | Customers tab label (matches existing `App.tsx:246`) |

**Two-line picker/list row pattern (locked by D-04 and D-12):**
- Line 1: `text-sm font-medium text-white` — customer name
- Line 2: `text-sm text-slate-400` — `{email} · {company}` (em-dash if either is empty; render only the present part if both are empty render nothing)
- Right rail: `text-sm text-slate-400` — `Last used: {relative}` or `Last used: Never used`

**No `font-bold`, no `text-base` (16px), no `text-xl`+ in this phase.** Existing primitives may render `text-base` on mobile inputs (`Input.tsx` `sizeStyles`), which is correct iOS no-zoom behavior — do not override.

**Per-row Edit button** uses `<Button variant="ghost">` (slate-300 on slate-700-hover). **Per-row Delete button** uses `<Button variant="ghost">` with `className="text-red-400 hover:text-red-300"` — matches AssetLibrary.tsx:402-409 precedent. Do NOT use `variant="danger"` on row-level delete (visual weight is wrong for a list row).

## Component Inventory

Surfaces this phase ships, with their composition spelled out so the executor needs no further design judgement:

### 1. Customers tab (main nav)
- Host: new `<button>` in the `tabs.map(...)` block of `App.tsx:242`.
- Label: `Customers` (full + short — same string, matching CONTEXT D-12 footnote).
- Wrap classes: copy verbatim from existing tab buttons (`px-2 sm:px-4 py-3 text-xs sm:text-sm font-medium transition-colors relative whitespace-nowrap min-h-[44px] flex items-center gap-1`).
- NewBadge: `<NewBadge feature="customer-library" className="absolute -top-1 -right-1 pointer-events-none" />` — placed as a sibling INSIDE the `<button>` (button is already `relative` per the existing tab pattern). **Locked by project rule** — never inline.

### 2. `CustomerLibrary.tsx` (Customers tab body)
**Layout (mirrors AssetLibrary.tsx):**
- **Heading row:** `<h2 className="text-lg font-semibold text-white">Customers</h2>` on the left; two action buttons on the right: `<Button variant="primary" btnSize="md">Add customer</Button>` and `<Button variant="secondary" btnSize="md">Import CSV</Button>`. Stack vertically on mobile (`flex flex-col sm:flex-row sm:items-center sm:justify-between gap-3`).
- **Search input:** Full-width `<Input placeholder="Search by name, email, or company">` with a left-anchored search icon (inline SVG, `w-4 h-4 text-slate-400`). Debounced filtering at 0 ms (synchronous — the dataset is small per Phase 11 conventions). Filter scope: Name + Email + Company per D-15.
- **List body (zero state):** `<EmptyState icon={<UsersIcon />} title="No customers yet" description="Add your first customer to start saving buyer details for re-use on future sales." cta={{ label: 'Add customer', onClick: openAddModal }} />`.
- **List body (loading state):** Use `<Skeleton variant="line">` placeholders modeled on `AssetListSkeleton` in AssetLibrary.tsx:22-91 — 3 mobile cards or 5 desktop rows. Skeleton shape MUST match the real row shape to avoid layout jump.
- **List body (populated state):** `react-window` `<List>` with `useDynamicRowHeight`, list rows rendered by a module-scope memoized component (precedent: AssetLibrary.tsx:142 "CR-01 fix").

**Row layout (locked by D-12, sort order locked below):**
- Container: `bg-slate-800/50 rounded-xl p-4 border border-slate-700/50` (mobile) / desktop grid row with same chrome.
- Line 1: `text-sm font-medium text-white truncate` — `{customer.name || '(no name)'}`.
- Line 2: `text-sm text-slate-400 truncate` — `${email}${email && company ? ' · ' : ''}${company}` (em-dash separator only when both are present).
- Right rail (desktop only — collapses below line 2 on mobile): `text-sm text-slate-400 whitespace-nowrap` — `Last used: {relative}` per "Last used rendering" below.
- Actions (right edge): `<Button variant="ghost" btnSize="sm">Edit</Button>` + `<Button variant="ghost" btnSize="sm" className="text-red-400 hover:text-red-300">Delete</Button>`. **Mobile:** icon-only (pencil + trash inline SVG, `w-4 h-4`), label hidden via `<span className="sr-only">`. **Desktop (`sm+`):** icon + label.

**Default sort order (LOCKED):** `lastUsedAt desc`, with `undefined` (never-used) records appearing FIRST (so newly-created customers don't disappear below long-used regulars). Tiebreaker: `name asc`. Search results retain the same sort.

**"Last used" rendering (LOCKED):**
- If `lastUsedAt === undefined`: render literal string `Never used` in `text-slate-400` (no relative date).
- If `lastUsedAt` is set: render `{Intl.RelativeTimeFormat('en', { numeric: 'auto' })}` output — e.g. `today`, `yesterday`, `3 days ago`, `last week`, `2 months ago`. **No new deps** — `Intl.RelativeTimeFormat` is native. Helper utility lives in `src/utils/` (planner decides exact filename; e.g. `formatRelativeDate.ts`).
- Tooltip: hover/focus shows the absolute ISO date via `title="{customer.lastUsedAt.toISOString()}"`.

### 3. `CustomerEditModal.tsx` (Create + Edit)
- **Chrome:** Same overlay pattern as `CsvImportModal.tsx:152-186` — fixed-position `inset-0 z-50 flex items-center justify-center p-4 bg-black/50`, panel `bg-slate-800 rounded-xl border border-slate-700 w-full max-w-md shadow-xl`. Click on backdrop dismisses; Escape dismisses.
- **Header:** `text-lg font-semibold text-white` — title text `Add customer` (create mode) or `Edit customer` (edit mode); right-side X-close `<Button variant="ghost" btnSize="sm">` with `w-5 h-5` close icon.
- **Body:** `space-y-4 p-4` form with 5 fields in this order: **Name → Email → Company → Address → Notes** (locked by D-13).
  - **Name** — `<Input>` (full-width, NOT `compact` — Customer text fields are not numeric per Phase 13 D-14). Label: `Name *`. No placeholder.
  - **Email** — `<Input type="email">`. Label: `Email *`. Placeholder: `customer@example.com`.
  - **Company** — `<Input>`. Label: `Company`. Placeholder: `Acme Co.`.
  - **Address** — `<Textarea rows={3}>`. Label: `Address`. No placeholder.
  - **Notes** — `<Textarea rows={3}>`. Label: `Notes`. Placeholder: `Buyer preferences, packaging quirks, etc.`.
- **Required-field signaling (LOCKED):** Per D-09, the rule is "Name OR Email" — neither is independently required. Render an asterisk on **both** Name and Email labels (`Name *`, `Email *`) AND a single-line helper above the form: `<p className="text-xs text-slate-400 mb-2">Provide at least one of Name or Email.</p>`. Submit-button is disabled when both are blank; validation error appears inline above the form as `text-sm text-red-400` if the user tries to save anyway.
- **Footer:** `<Button variant="ghost" btnSize="md">Cancel</Button>` + `<Button variant="primary" btnSize="md" type="submit">Save customer</Button>` — right-aligned `flex justify-end gap-2 pt-2 border-t border-slate-700`.
- **Close-on-save behavior (LOCKED):** On successful save the modal closes and the parent list re-renders via `useLiveQuery`. No toast. Matches the existing AssetLibrary edit flow.

### 4. `CustomerCsvImportModal.tsx` (Import CSV)
- **Chrome + step model:** Mirror CsvImportModal.tsx structurally — two steps (`upload` → `preview`), same outer panel (`max-w-3xl max-h-[85vh] flex flex-col shadow-xl`), same header back-arrow + close-X pattern (CsvImportModal.tsx:159-186).
- **Header title:** `Import customers from CSV` (upload step) / `Preview customer import` (preview step).
- **Upload step:**
  - **Dropzone:** Match CsvImportModal — drag-and-drop area + native file picker fallback. Dashed border `border-2 border-dashed border-slate-600` (default) / `border-blue-500 bg-blue-500/5` (drag-over). Inline SVG cloud-upload icon (`w-12 h-12 text-slate-400 mx-auto`), helper copy `Drop a .csv file here, or click to browse`. Below the dropzone: a small `<Button variant="ghost" btnSize="sm">Download sample CSV</Button> · <Button variant="ghost" btnSize="sm">View column reference</Button>`.
  - **Column reference (expanded via button):** Plain copy block — `Accepted columns: name, email, company, address, notes. Column order doesn't matter. Headers are case-insensitive. Either name or email is required per row.`
  - **Error state:** Inline `bg-red-500/10 border border-red-500/30 text-red-400 text-sm rounded-lg p-3` block above the dropzone.
- **Preview step:**
  - **Stats bar:** `text-sm text-slate-400` line — `Found {N} rows · {Y} ready to import · {Z} skipped (duplicates) · {E} with errors`.
  - **Duplicate-mode radio:** Single horizontal radio group at the top of the preview body (locked by D-10). Labels: `Skip duplicates` (default checked) and `Update duplicates`. Below the active selection: `text-xs text-slate-400` explainer — for Skip: `Existing customers matched by email will not change.` — for Update: `Existing customers matched by email will be updated (only non-empty incoming fields overwrite — empty cells keep existing values).` (Explainer copy is load-bearing because D-11 merge semantics are non-obvious.)
  - **Row table:** Same columns as the customer list row, plus a leading checkbox column and a trailing status column. Status chip variants:
    - `OK` → `bg-green-500/20 text-green-400 border-green-500/30`
    - `Duplicate` → `bg-yellow-500/20 text-yellow-400 border-yellow-500/30`
    - `Error: {message}` → `bg-red-500/20 text-red-400 border-red-500/30`
  - **Row-level validation error copy (LOCKED):**
    - Both Name and Email blank → `Name or Email required`
    - Email present but malformed (no `@`) → `Email format invalid`
    - (Future-extension errors should follow the same `Field: condition` pattern.)
  - **Footer:** `<Button variant="ghost" btnSize="md">Cancel</Button>` + `<Button variant="primary" btnSize="md">Import {N} customer{s}</Button>` (count reflects the post-dedup-filter import count). Button label dynamically updates as the user toggles the duplicate radio.

### 5. Combobox picker in `JobsManager.tsx` Record Sale modal
- **Host position:** Single `<Input>` rendered directly above the existing 4-field Customer block (JobsManager.tsx:363 region per CONTEXT canonical_refs).
- **Label:** `<label className="text-sm text-slate-400">Existing customer</label>`. (Avoid "Search customer" — D-15 calls this the "picker.")
- **Placeholder:** `Type to find a saved customer…`
- **Dropdown panel (LOCKED Tailwind classes):** `absolute z-10 mt-1 w-full bg-slate-800 border border-slate-700 rounded-lg shadow-lg max-h-72 overflow-y-auto`.
- **Dropdown row:** `<button type="button" role="option">` with `w-full text-left px-4 py-3 hover:bg-slate-700 focus:bg-slate-700 focus:outline-none min-h-[44px]`. Two-line layout per D-04: line 1 `text-sm font-medium text-white`, line 2 `text-xs text-slate-400`. Active-descendant row (keyboard-focused): `bg-blue-500/10 text-blue-300`.
- **Match-limit (LOCKED):** Show first **8** matches. If more matches exist, render a non-interactive footer row: `<div className="px-4 py-2 text-xs text-slate-500 border-t border-slate-700">Showing first 8 of {M} matches — refine your search</div>`.
- **Empty-search-result state:** When typed query has 0 matches, render a single non-interactive row: `<div className="px-4 py-3 text-sm text-slate-400">No saved customers match "{query}". The customer will be saved when you record the sale.</div>` — this is the user-visible signal that D-06's silent auto-save will fire. **No "+ Add new" footer row** (D-06 explicitly rejected an explicit add button — the typeahead's job is dedup, not gating).
- **Pick interaction:** Click or Enter on a row fills Name/Email/Company/Address in the existing 4-field block (Notes is NOT auto-filled per D-05); bumps `customer.lastUsedAt = new Date()`; collapses dropdown; clears the picker input.

**Combobox keyboard semantics (LOCKED — full WAI-ARIA combobox pattern):**
- `role="combobox"` on the `<Input>`; `aria-expanded={isOpen}`; `aria-controls="customer-picker-listbox"`; `aria-autocomplete="list"`; `aria-activedescendant={activeId or undefined}`.
- Dropdown panel: `role="listbox" id="customer-picker-listbox"`. Each row: `role="option" id="customer-option-{id}"`.
- Keyboard map:
  - `ArrowDown` — open dropdown (if closed) OR move active row down; wraps from last → first.
  - `ArrowUp` — move active row up; wraps from first → last.
  - `Enter` — pick the active row (if any); otherwise no-op.
  - `Escape` — close dropdown without picking; leave query text in the input.
  - `Tab` — close dropdown, blur the input, advance focus to the next form field (do NOT auto-pick).

Rationale: the picker is a primary data-entry surface in the Record Sale modal; partial ARIA ("looks like a typeahead but isn't keyboard-friendly") would be a regression against an existing form that's accessible today.
