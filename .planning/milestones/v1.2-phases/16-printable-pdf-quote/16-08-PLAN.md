<objective>
Per gap H (D-21), the saved `job.taxRate` field currently stores the raw form-state `taxRateOverride` (which is `undefined` when the user leaves the field blank). The PDF generator at `src/pdf/generateQuotePdf.ts` reads `job.taxRate` directly — so a job created with a blank tax field and a non-zero `userProfile.defaultTaxRate` produces a PDF with NO tax row and a Total equal to Subtotal. The customer is undercharged silently.

The fix is one-line at each of two save sites: store `tax.ratePercent` (the resolver output) instead of `taxRateOverride` (raw form state). Plus a regression test and a Phase 13 Sale-write audit per D-21.

Purpose: Eliminate the silent-undercharge bug and lock the fix with a regression test.
Output: CostCalculator.tsx with both save sites corrected; a new vitest regression test proving blank-override + default-rate yields a non-zero saved `taxRate`; JobsManager Sale-write path audited (symmetric fix or audit-clean TODO).

**Critical note (CLAUDE.md "Problem-Solving Discipline"):** This is a save-boundary fix, NOT a resolver fix. The `resolveTaxRate` function in `src/utils/taxResolution.ts` already correctly produces the resolved rate (Phase 13 / 13-02 SUMMARY). The defect is at the save boundary. Do not touch the resolver.
</objective>
