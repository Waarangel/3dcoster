<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user input → modal | Keyboard events (Tab/Shift+Tab/Escape) and mouse events flow through the focus-trap + close handlers — must not crash on malformed events |
| consumer → Modal | Consumers pass arbitrary children — Modal must not assume children have focusable descendants |
| dev-only → prod | `console.warn` for single-modal violation is dev-only — production must never crash or log |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19-01 | Tampering | `document.body.style.overflow` scroll-lock | mitigate | Capture prior value at mount; restore exact prior value on unmount (do not just clear) — prevents clobbering parent code that manages overflow |
| T-19-02 | Denial of service | Focus trap re-query loop | mitigate | Re-query only on Tab keystroke (not in a setInterval); throttled by user input rate |
| T-19-03 | Information disclosure | `console.warn` in production | mitigate | Gate warn on `process.env.NODE_ENV !== 'production'` — no log in prod builds |
| T-19-04 | Elevation of privilege | Single-modal-only guard | accept | Module-level flag is not a security boundary; it's a developer hygiene check. Bypassable trivially but no privilege impact. |
</threat_model>
