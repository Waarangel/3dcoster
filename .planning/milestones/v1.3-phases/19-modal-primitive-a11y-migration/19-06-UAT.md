# Phase 19 VoiceOver UAT — Modal Surface + Virtualized List Smoke Test

## Status: Deferred (not blocking Phase 19)

Per `19-CONTEXT.md` discretion block, VoiceOver UAT failures are NOT Phase 19 blockers — they are scoped as v1.4+ follow-on items. The structural a11y work (WAI-ARIA dialog pattern in Modal primitive, label/input pairing via htmlFor, role=list/listitem/grid on virtualized lists) is complete and verified by automated tests in plans 19-01 → 19-06. The manual screen-reader smoke test below is captured here as a scheduled-but-deferred quality check.

## Test Plan

### Setup
1. `npm run dev` (port 4173 — pinned in `vite.config.ts`).
2. Open Safari (VoiceOver works best in Safari on macOS; Chrome/Firefox also supported).
3. Toggle VoiceOver: `Cmd+F5`.

### Per-surface assertions
For each modal surface:
- **A**: VoiceOver announces "dialog" (or "web dialog") and reads the modal title within 1 second of opening.
- **B**: Tab cycles within the modal — focus does not escape to the background page.
- **C**: Escape closes the modal; VoiceOver announces the page or returns to a sensible focus target.
- **D**: Focus returns to the trigger element (or `document.body` if the trigger was unmounted).

### Per-list assertions
For each virtualized list:
- **E**: VoiceOver announces "list, N items" (where N is the visible row count).
- **F**: Stepping through rows, VoiceOver announces each row as a list item (or row, for grid-wrapped tables).
