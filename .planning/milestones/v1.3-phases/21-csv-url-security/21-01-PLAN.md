<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User input → IndexedDB | Asset names, brands, notes, tags, currencies are typed by the user and stored verbatim (permissive string store). No escaping at the storage boundary — by design. |
| IndexedDB → CSV export → External spreadsheet | User-typed strings re-enter an external trust domain (Excel / LibreOffice / Numbers) which interprets cells starting with `=`, `+`, `-`, or `@` as formulas. THIS is the boundary we harden. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21-01 | Tampering (CWE-1236 — Improper Neutralization of Formula Elements in a CSV File) | `generateExportCsv` (highest-risk site — wraps user-typed asset names/notes/brands/tags) | mitigate | Wrap every output cell in `sanitizeCsvCell` at the cell-serialization boundary (D-03). Behavior locked by `csvHelpers.test.ts` SEC-01 describe block. OWASP class: "CSV Injection" (a.k.a. Formula Injection). |
| T-21-02 | Tampering | `generateSampleCustomerCsv`, `generateSampleCsv` (template generators with hardcoded data) | mitigate (defense in depth) | Universal coverage per D-02 — even though current template strings are no-op (none start with a trigger), wrapping them keeps the invariant grep-enforceable so future template edits cannot regress. Cost: zero runtime, structural-only. |
| T-21-03 | Information Disclosure | Excel `HYPERLINK("https://evil.com","click")` formula in an exported asset cell | mitigate via T-21-01 | The single-quote prefix demotes the cell to a literal string; the spreadsheet renders `=HYPERLINK(…)` verbatim instead of executing it (Manual UAT criterion #5 in ROADMAP). |
| T-21-SC | Tampering | npm/pip/cargo installs | accept | No new dependencies introduced by this plan. `papaparse` is already pinned (Phase 19 audit baseline). |

## Residual Risks (Explicitly Deferred per 21-CONTEXT.md `<deferred>`)

- **CRLF injection in CSV cells** — a value containing `\r\n` could break out of a quoted CSV cell on some readers. `Papa.unparse` already quote-wraps multi-line strings (verified by reading Papa docs); residual risk is low. NOT explicitly tested in this plan. (Deferred unless a real-world exploit surfaces.)
- **UTF-8 BOM injection / Byte-order-mark spoofing** — exported CSV does not prepend a BOM today. NOT in scope.
- **Encoded payloads** — Unicode look-alikes of `=` (e.g., U+FF1D `＝`) are NOT in the trigger set. Excel does not treat them as formula triggers either, so this is by design. Deferred unless a CVE surfaces.
- **Customer CSV export path** — `customerCsv.ts` has no exporter today (D-02 / 21-CONTEXT.md `<deferred>`). Adding one is a separate phase; the universal-coverage invariant in `csvHelpers.ts` ensures any future export path that lands in this file inherits sanitization.

**ASVS Level 1 mapping:** V5.3.2 (Output encoding — ensure output is encoded for the consuming interpreter). Severity: HIGH (per v1.2-CODE-AUDIT.md finding #5).
