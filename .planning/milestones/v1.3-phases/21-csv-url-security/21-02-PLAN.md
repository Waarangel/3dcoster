New module to create:

  // src/utils/urlSecurity.ts
  export function isSafeHttpUrl(value: string | undefined): boolean;

Rule (per D-04):
  1. If `value` is undefined → false
  2. Otherwise: let `s = value.trim().toLowerCase()`
  3. Return `s.startsWith('http://') || s.startsWith('https://')`

This rejects: empty string, whitespace-only, `javascript:*`, `data:*`, `vbscript:*`, `file:*`, `mailto:*`, plain words like `"foo"`, `http:foo` (no slashes — `http:` alone does not match `http://`).

This accepts: `http://example.com`, `https://example.com`, `HTTP://Example.com` (case-normalized), `  https://example.com  ` (trimmed), `JavaScript:alert(1)` does NOT match because after lowercase it becomes `javascript:alert(1)`, which does not start with `http://` or `https://`.

From src/components/JobsManager.tsx (the SINGLE render site of `modelUrl` as a link — confirmed by grep `modelUrl` returning only lines 616, 620, 626):

The block to wrap (currently at lines 616-629; line number may have drifted — locate by the literal `'Model source: '` label followed by `<a href={job.modelUrl}`):

  {job.modelUrl && (
    <div className="mb-4 text-sm">
      <span className="text-slate-500">Model source: </span>
      <a
        href={job.modelUrl}
        target="_blank"
        rel="noopener noreferrer"
        onClick={(e) => e.stopPropagation()}
        className="text-blue-400 hover:text-blue-300 underline break-all"
      >
        {job.modelUrl}
      </a>
    </div>
  )}

After the guard, the inner structure becomes a ternary: when `isSafeHttpUrl(job.modelUrl)` → render the existing `<a …>` exactly as is; when false → render a plain `<span title="…">{job.modelUrl}</span>` (D-07: plain text, not omitted; with a `title` warning).

The outer `{job.modelUrl && (…)}` truthy guard stays — empty/undefined URLs continue to render NOTHING (no row label, no fallback). The new branch only applies when `job.modelUrl` is non-empty but fails `isSafeHttpUrl`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User input (CostCalculator form) → IndexedDB | `job.modelUrl` is typed by the user and stored verbatim in IndexedDB. No save-time validation (D-06: deferred). |
| IndexedDB → React render → DOM `<a href>` | The DOM treats `href="javascript:..."` as an executable URL scheme. Clicking such a link runs the payload in the page's origin → stored XSS. THIS is the boundary we harden. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21-04 | Tampering / Elevation of Privilege (CWE-79 — Improper Neutralization of Input During Web Page Generation, Stored XSS variant) | `<a href={job.modelUrl}>` in `JobsManager.tsx` Model source block | mitigate | Render-time `isSafeHttpUrl(job.modelUrl)` guard. Invalid → plain-text `<span title="…">` fallback. OWASP class: A03:2021 — Injection (XSS subclass). |
| T-21-05 | Information Disclosure | `data:text/html,...` URLs that render a phishing page when clicked | mitigate via T-21-04 | The prefix check rejects `data:` along with `javascript:` / `vbscript:` / `file:` schemes. |
| T-21-06 | Tampering | `JavaScript:` (case variants) bypassing a naive case-sensitive check | mitigate | The helper applies `toLowerCase()` BEFORE the prefix check (D-04 step 2). Locked by the `JavaScript:alert(1)` test case in D-05. |
| T-21-07 | Tampering | Whitespace-padded `  javascript:alert(1)` bypassing a naive raw-string check | mitigate | The helper applies `trim()` BEFORE `toLowerCase()` (D-04 step 2). Locked by the `  javascript:alert(1)` test case in D-05. |
| T-21-SC | Tampering | npm/pip/cargo installs | accept | No new dependencies introduced by this plan. |

## Residual Risks (Explicitly Deferred per 21-CONTEXT.md `<deferred>`)

- **Save-time UX feedback** — typing `javascript:alert(1)` into the Model URL field still saves to IndexedDB and renders as a plain-text fallback on the next view. There is no inline form-validation error, no toast, no disable-save logic. D-06 + 21-CONTEXT.md `<deferred>`: out of scope; the render-time guard fully neutralizes the attack vector. Future UX-quality phase can add this with the same `isSafeHttpUrl` helper.
- **`new URL()` parsing for richer validation** — would catch URL-encoded payloads (`http%3A%2F%2F…`), unusual hostnames, and `http:` without slashes more cleanly. The prefix check is sufficient for the in-scope schemes (`javascript:`, `data:`, `vbscript:`, `file:`); deferred unless a real-world exploit surfaces. 21-CONTEXT.md `<deferred>` records this.
- **Hostname spoofing** (`https://evil.com/login@bank.com`) — `isSafeHttpUrl` validates the SCHEME only, not the hostname. By design: hostname trust is a separate concern (typo-squatting / homograph attacks) and is not in v1.3 scope.
- **PDF embedder broadening** — `src/pdf/generateQuotePdf.ts` does not currently embed user-typed URLs as clickable links. Out of scope per 21-CONTEXT.md `<code_context>`: "do not broaden the integration as part of this phase (deferred)".

**ASVS Level 1 mapping:** V5.3.3 (Output encoding ensures that scripts are not embedded as executable URL schemes in HTML anchor tags). Severity: HIGH (per v1.2-CODE-AUDIT.md finding #6).
