**Two Phase 22 code-review warnings closed: WR-01 removes a dead userProfile prop from RecordSaleModal's interface (and from its JobsManager callsite); WR-02 narrows the hydration useEffect dep array so concurrent useLiveQuery emissions can't clobber in-progress edit form state. ## Accomplishments

- **WR-01 closed (D-10).** `RecordSaleModalProps` no longer declares the dead `userProfile: UserProfile` field. `UserProfile` is dropped from the modal's type imports. The `<RecordSaleModal>` callsite in `JobsManager.tsx` (line 1419) no longer passes `userProfile={userProfile}`. The sibling `<PrintQuoteModal>` callsite (line 1490) still passes `userProfile={userProfile}` — that's a different component that legitimately consumes the prop and is untouched.
- **WR-02 closed (D-09).** Hydration `useEffect` dep array narrowed from `[editingSale, convertingFromQuote, job.sellingPrice]` to `[editingSale?.id, convertingFromQuote?.id]`. A concurrent `useLiveQuery` emission that updates `job.sellingPrice` while the modal sits open in EDIT or CONVERT mode no longer re-fires the hydration effect — protecting the user's in-progress form state.
- **Pitfall 3 + Pitfall 6 honored.** Four-line Pitfall 3 explanation comment sits directly above the new dep array (lines 154-158), and the eslint-disable-next-line directive is anchored to it. The comment explicitly references Phase 22.1 D-09 / WR-02 so future developers don't "fix" the dep array back to its broader form.
- **WR-02 regression test locked.** New `WR-02 — hydration dep array stability (Phase 22.1 D-09)` describe block in `RecordSaleModal.test.tsx` renders the modal in EDIT mode (editingSale.unitPrice=50), reads the salePrice input, re-renders with a mutated job (sellingPrice=999), and asserts the salePrice input still reads '50'. Test passed at Task-1-RED time too (because the EDIT branch resets to editingSale.unitPrice regardless of when it re-fires), but the dep-array narrowing in Task 2 locks the behavior even if branch logic ever changes.

## Deviations from Plan

**None. Plan executed exactly as written.**

One ancillary cleanup happened in the test file that the plan didn't pre-specify but is the direct consequence of D-10 + tsconfig's `noUnusedLocals: true`:

- After removing `userProfile` from the interface, the test's `renderModal` builder spreads props into `<RecordSaleModal {...props} />`. Leaving `userProfile: makeUserProfile()` in that builder would compile fine (excess property in spread is allowed) — but the `makeUserProfile` helper itself becomes unused, and `UserProfile` from `../types` becomes an unused import. tsc -b's `noUnusedLocals: true` + `noUnusedParameters: true` flags would have failed. Removing the prop, the helper, and the import together is the minimal Rule 3 auto-fix that keeps tsc clean.

The plan's `<files>` block for Task 2 only lists `RecordSaleModal.tsx` + `JobsManager.tsx`, so the test-side cleanup arguably falls outside Task 2's declared scope. I bundled it into the Task 2 commit (a single coherent refactor) rather than splitting it into a third commit — the unused-locals errors are a direct consequence of the interface change and surface together.
