## Schema shape

| Option | Description | Selected |
|--------|-------------|----------|
| Nested object: `fixedCostsAtSave: { depreciation, nozzleWear }` (Recommended) | One field, easy to extend later. Mirrors PrintJob.customer { name, email } pattern. | ✓ |
| Flat fields: `printerDepreciationAtSave`, `nozzleWearAtSave` | Two top-level fields. Simpler access. Harder to extend. | |
| Combined total: `fixedCostsAtSaveTotal: number` (just the sum) | One number, lossy. Means JobsManager can't show breakdown later. | |

**User's choice:** Nested object — `fixedCostsAtSave: { depreciation, nozzleWear }`
**Notes:** Future-proof for extra fixed-cost categories (printer hourly rate, packaging amortization) without needing another schema migration.

## Missing-printer edge case

| Option | Description | Selected |
|--------|-------------|----------|
| Snapshot to 0 + log a warning (Recommended) | Job becomes break-even-on-modelCost-only — no surprise vs today's pill behavior. console.warn surfaces orphan. Reconcile flag still flips (idempotent). | ✓ |
| Snapshot from the first available printer (fallback) | Pick any active printer's settings. Hides data quality issues. | |
| Skip the job (leave fixedCostsAtSave undefined) | computeBreakEvenInfo falls back to legacy formula for that job. Could leave reconcile flag permanently stuck. | |
| Surface a one-time prompt asking user to map orphans | Modal listing orphan jobs. More UX work; not worth it for a hardening phase. | |

**User's choice:** Snapshot to 0 + log a warning
**Notes:** Matches today's pill behavior for affected jobs (no user-visible surprise); orphan jobs surface in console for power users; reconcile flag flips cleanly.

## Reconcile trigger

| Option | Description | Selected |
|--------|-------------|----------|
| Once on app startup behind a Dexie meta-row flag (Recommended) | Mirrors Phase 16 `backfillQuotesFromJobs` / Phase 20 `reconcileQuoteCurrency`. Meta row `phase22_1_breakEvenReconcileV1` = `done` after first successful run. Idempotent. | ✓ |
| Tied to a Dexie schema bump (v8→v9 migration) | Cleanest provenance but heavyweight; explicit success criterion forbids the bump. | |
| On first JobsManager render (lazy) | Defers cost but risks Calculator-only users never reconciling. Fragile (runs inside React render). | |
| On every app startup (no idempotency) | Recomputes for every legacy job on every launch — wasteful; computeBreakEvenInfo already handles `undefined` gracefully so this is unnecessary. | |

**User's choice:** Once on app startup behind a Dexie meta-row flag
**Notes:** Mirrors `reconcileCopiesSoldFromSales` invocation precedent in [src/db/backfill.ts](../../../src/db/backfill.ts). Researcher locates the exact wire-up site (App.tsx vs useDatabase.ts).

## Edit-time policy

| Option | Description | Selected |
|--------|-------------|----------|
| Preserve the saved snapshot; overwrite only on next Save (Recommended) | Calculator's UI re-computes the LIVE numbers for display, but the saved snapshot stays put until user clicks Save. Matches today's costPerUnit behavior. | ✓ |
| Always recompute from current printer settings (no user action needed) | Edit re-hydrates form, recomputes snapshot, writes new snapshot even without Save click. Hides data drift. Inconsistent with costPerUnit / sellingPrice. | |
| Show both saved and current values; let user choose which to keep | Two side-by-side numbers in the form during Edit. Most honest, but adds UX complexity for a number users barely interact with. | |

**User's choice:** Preserve the saved snapshot; overwrite only on next Save
**Notes:** Jobs are immutable snapshots until re-saved. Matches the rest of the cost-input persistence model.
