The cache automatically measures each rendered row's actual height, which handles both the 88px-collapsed and 400px-expanded cases without manual height math. Selection-driven invalidation uses the v2-idiomatic `key` arg — when `selectedJobId` changes, the cache is rebuilt automatically. There is NO `.reset()` method on the cache object in v2 (it does not exist in the type definitions).

react-window v2 `<List>` (verified canonical API):
```
<List
  rowComponent={Row}        // React component; required signature includes ariaAttributes/index/style
  rowCount={number}         // number of rows
  rowHeight={number | string | function | DynamicRowHeight}
  rowProps={object}         // additional props passed to rowComponent (CANNOT contain index, style, ariaAttributes)
  defaultHeight={number}    // initial render height before measurement (SSR-safe)
  overscanCount={number}    // extra rows rendered outside viewport (default fine)
  tagName={string}          // override the SINGLE root element (default "div"). There is NO separate inner-element override.
  listRef={ref}             // imperative scroll API
  className={string}        // CSS class
  style={object}            // CSS for the outer scroll container
  onResize, onRowsRendered  // callbacks (not needed here)
/>
```

The exported hook for dynamic row heights:
```ts
export declare function useDynamicRowHeight({ defaultRowHeight, key }: {
  defaultRowHeight: number;    // REQUIRED
  key?: string | number;       // optional — CHANGE THIS to invalidate the cache
}): DynamicRowHeight;
```

The returned `DynamicRowHeight` object exposes:
- `getAverageRowHeight()`, `getRowHeight(index)`, `setRowHeight(index, size)`, `observeRowElements(elements)`
- **THERE IS NO `.reset()` METHOD.** Cache invalidation is achieved by passing a different `key` arg on next render.

`rowComponent` receives, on every render, an `ariaAttributes` prop (object with `aria-posinset`, `aria-setsize`, `role: 'listitem'`), plus `index`, `style`, and any `rowProps` fields. Calling the row component directly (e.g., in a non-virtualized fallback) WITHOUT supplying `ariaAttributes` causes TS error TS2741. The pattern used in this plan to sidestep that error: a plain `JobCard` component (no `RowComponentProps` typing) and a thin `JobRow` adapter typed as `RowComponentProps<...>` that delegates to JobCard. The small-list branch renders JobCard directly; the virtualized branch passes JobRow to `<List>`'s `rowComponent` slot.
