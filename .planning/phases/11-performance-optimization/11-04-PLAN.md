<objective>
Virtualize JobsManager's `jobs.map(...)` rendering at line 237 per D-06, using react-window v2's `<List>` component. Apply the virtualized branch only when `jobs.length > 100`; below 100, keep the existing flat `<div className="space-y-3">` render unchanged. Resolve design Q2 (bimodal row height — ~88px collapsed, ~400px expanded) using react-window v2's `useDynamicRowHeight` hook with cache reset on selection toggle. This is the v2 replacement for v1's `VariableSizeList` + `resetAfterIndex` pattern.

Purpose: Satisfies the JobsManager half of PERF-02. After this plan, a user with 500+ saved jobs can scroll the list smoothly even under 4× CPU throttle (the manual UAT in Plan 06 verifies this).

Output: Updated `JobsManager.tsx` with a conditional virtualized branch, a `<Row>` sub-component, and selection-driven row-height management.

**Design Q2 resolution recorded in this plan:** D-08 biased toward `FixedSizeList`. Given the verified react-window v2 API (no `FixedSizeList`/`VariableSizeList` — only the unified `<List>` with `rowHeight` accepting a number OR a function OR a `useDynamicRowHeight` cache), the cleanest expression of "fixed sizing biased, dynamic only if breakage" is: use `useDynamicRowHeight` with a measurement cache. The cache automatically measures each rendered row's actual height, which handles both the 88px-collapsed and 400px-expanded cases without manual height math. The "fixed" intent from D-08 is preserved by setting a sensible `defaultHeight` (88px — the collapsed measurement) so initial render before measurement is correct.
</objective>

react-window v2 `<List>` (verified canonical API):
```
<List
  rowComponent={Row}        // React component, receives { index, style, ...rowProps }
  rowCount={number}         // number of rows
  rowHeight={number | string | function | useDynamicRowHeight cache}
  rowProps={object}         // additional props passed to rowComponent (excludes index, style, ariaAttributes)
  defaultHeight={number}    // initial render height before measurement (SSR-safe)
  overscanCount={number}    // extra rows rendered outside viewport (default fine)
  tagName={string}          // override root element (default "div")
  listRef={ref}             // imperative scroll API
  className={string}        // CSS class
  style={object}            // CSS for the outer scroll container
  onResize, onRowsRendered  // callbacks (not needed here)
/>
```
The exported hook for dynamic row heights: `useDynamicRowHeight()` — returns a cache object. Pass the cache directly as `rowHeight={cache}`. The cache exposes `.reset(index)` to invalidate a specific row's measurement when its content changes (e.g., selection toggles).

`RowComponentProps` typings are exported from `react-window` for TypeScript convenience.

Pattern reference — useDynamicRowHeight + selection-driven reset (v2 idiom):
```
const rowHeightCache = useDynamicRowHeight();

useEffect(() => {
  // When selection changes, the previously-selected row collapses and the
  // new one expands. Reset both to force re-measurement on next render.
  if (prevSelectedRef.current !== null) rowHeightCache.reset(indexOfPrev);
  if (selectedJobId !== null) rowHeightCache.reset(indexOfNew);
  prevSelectedRef.current = selectedJobId;
}, [selectedJobId, jobs]);
```
The hook handles the layout automatically once `reset` is called.
