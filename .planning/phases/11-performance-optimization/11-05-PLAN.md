<objective>
Virtualize AssetLibrary's three `paginatedAssets.map(...)` call sites (lines ~848 mobile cards, ~987 printers table, ~1057 materials table) when `effectiveItemsPerPage > 50` per D-07. Resolve design Q1 (how to virtualize inside a `<table><tbody>` semantic structure) by converting the two desktop tables to `<div>`-based grids (using Tailwind grid classes with `role` ARIA attributes for accessibility-equivalent semantics).

**Design Q1 resolution recorded in this plan:** PATTERNS.md surfaced three options for the two table call sites: (a) replace `<table>` with div-grid when virtualized, (b) use react-window v2's `outerElementType`/`innerElementType` (v1 names — these props DO NOT EXIST in v2), or (c) skip virtualizing tables. After verifying the v2 API against react-window@2.2.7/dist/*.d.ts, option (b) as originally described is moot — v2 exposes ONLY a single `tagName` prop, not separate outer/inner overrides. Iteration 1 of the plan proposed a hybrid: `tagName="tbody"` + `<colgroup>` + `display: block`. Plan-checker iteration 1 surfaced that this is structurally broken — `<col>` widths only apply in CSS table layout, which is destroyed once `<tbody>` becomes `display: block` for absolute row positioning. Therefore option (a) — replace `<table>` with `<div>`-grid — is now the PRIMARY (and ONLY) approach for the two table call sites. The trade-off: loss of `<table>` / `<thead>` / `<tbody>` / `<tr>` / `<td>` markup, mitigated by adding `role="row"` / `role="columnheader"` / `role="cell"` ARIA attributes to the replacement `<div>` elements.

- **Mobile cards (line 848):** `<List>` with default `tagName="div"`. A plain `MobileCardItem` component renders the existing `<div className="bg-slate-800/50 rounded-xl p-4 ...">` card; a thin `MobileCardRow` adapter typed as `RowComponentProps<...>` wraps it for the `<List>` slot. Clean fit; no semantic concerns.
- **Desktop printer table (line 987):** Replace the `<table>` ENTIRELY with `<div>`-based grid markup using Tailwind grid classes. Plain `PrinterRow` component renders the row; `PrinterRowAdapter` (typed as `RowComponentProps<...>`) wraps it for `<List>`. The header `<thead><tr><th>` becomes `<div role="row"><div role="columnheader">`. Sort header `onClick` handlers move from `<th>` to the corresponding `<div role="columnheader">` children.
- **Desktop materials table (line 1057):** Same treatment as the printer table, with `MaterialRow` (plain) and `MaterialRowAdapter` (RowComponentProps-typed).

The BLOCKER 3 fix from iteration 1 sidesteps the `RowComponentProps` ariaAttributes requirement by typing only the adapters with `RowComponentProps`; the plain Row components have their own minimal types and are rendered directly in the small-list branches.

Purpose: Satisfies the AssetLibrary half of PERF-02 while honoring D-07's "all three must be virtualized when triggered" requirement. Pagination remains the primary chunking strategy; virtualization only kicks in for the power-user "100/page" or "All" cases.

Output: Updated `AssetLibrary.tsx` with three conditional virtualization branches, two tables replaced by div-grid markup, and six row sub-components (three plain + three adapters).
</objective>
