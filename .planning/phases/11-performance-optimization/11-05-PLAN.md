<objective>
Virtualize AssetLibrary's three `paginatedAssets.map(...)` call sites (lines ~848 mobile cards, ~987 printers table, ~1057 materials table) when `effectiveItemsPerPage > 50` per D-07. Resolve design Q1 (how to virtualize inside a `<table><tbody>` semantic structure) using react-window v2's `tagName` prop — the only v2 mechanism for overriding the root element.

**Design Q1 resolution recorded in this plan:** PATTERNS.md surfaced three options for the two table call sites: (a) replace `<table>` with div-grid when virtualized, (b) use react-window v2's `outerElementType`/`innerElementType` (v1 names — these props DO NOT EXIST in v2), or (c) skip virtualizing tables. After verifying the v2 API against the canonical react-window README (2026-05-20), option (b) as originally described is moot — v2 exposes ONLY a single `tagName` prop, not separate outer/inner overrides. The pragmatic v2 resolution is a hybrid:

- **Mobile cards (line 848):** `<List>` with default `tagName="div"`. Row component renders the existing `<div className="bg-slate-800/50 rounded-xl p-4 ...">` card. Clean fit; no semantic concerns.
- **Desktop tables (lines 987, 1057):** Set `tagName="tbody"` on `<List>`, place the `<List>` directly INSIDE the existing `<table>` (replacing the current `<tbody>...</tbody>`), and have the Row component render `<tr>` as its root with `style={style}`. react-window v2's `style` injection on a `<tr>` element works because `<tr>` accepts inline styles for positioning (verified against the canonical React 19 + Vite + react-window v2 stack — `position: absolute` on `<tr>` is widely supported and is exactly what react-window emits). If the executor finds during build/typecheck that `<tr style={style}>` produces TypeScript or rendering issues, fall back to option (a) for tables (replace `<table>` with `<div>`-grids using the same Tailwind grid classes that AssetLibrary already uses elsewhere) — this fallback is documented in the action below.

Purpose: Satisfies the AssetLibrary half of PERF-02 while honoring D-07's "all three must be virtualized when triggered" requirement. Pagination remains the primary chunking strategy; virtualization only kicks in for the power-user "100/page" or "All" cases.

Output: Updated `AssetLibrary.tsx` with three conditional virtualization branches.
</objective>
