## Notes

**Per D-07 (CONTEXT.md):** This plan adds `quoteNumber?: number` to `PrintJob` BEYOND the explicit four-field list in SCHEMA-01 (which only enumerates `tags`, `customer`, `taxRate`, `taxAmount`). The extension is in scope for Phase 12 because the field MUST land in the v6 schema before Phase 16 (PDF) starts — the alternative (re-incrementing on every PDF regenerate) would be a UX bug per D-05. Rationale chain: D-05 locks the "store quote number on job, reuse on regenerate" design; D-06 locks `nextQuoteNumber` default = 1; D-07 explicitly authorizes adding `quoteNumber?` to `PrintJob` and instructs the planner to call it out here. The field stays undefined on existing v5 records (no migration backfill — Phase 16 assigns it on first PDF generation).
