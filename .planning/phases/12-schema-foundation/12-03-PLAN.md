<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| IndexedDB → migrator | Existing v1.0/v1.1 user rows enter the v6 upgrade callback. Already mitigated upstream by Plan 02's `Array.isArray` defensive guard. |
| Browser tab A ↔ tab B (IndexedDB cross-tab `versionchange` event) | Tab B opens on a newer schema → IndexedDB fires `versionchange` on tab A's open connection. If unhandled, Dexie's default closes the connection + `console.warn`s, leaving the React tree referencing a dead handle (white-screen crash). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-03-01 | Denial of Service (data loss during partial migration) | v6 `upgrade(tx => ...)` callback | mitigate | The `return` keyword on `tx.table('jobs').toCollection().modify(backfillTagsOnJob)` ensures Dexie awaits every row's mutation before reporting v6 ready. Without it, v6 could be marked complete while some rows still have `tags: undefined`, causing intermittent `TypeError` in Phase 15 readers (RESEARCH Pitfall 2; STATE.md "Dexie v5 migration returns modify() promise to ensure complete record conversion" — v1.0 lesson explicitly cited). Acceptance criteria grep-asserts the `return` keyword is present. |
| T-12-03-02 | Denial of Service (white-screen crash) | Multi-tab `versionchange` event | mitigate | `db.on('versionchange', () => window.location.reload())` registered at module-top-level (BEFORE `export { db };`) so the handler attaches synchronously during module evaluation, before any `useLiveQuery` consumer fires `db.open()` (RESEARCH Pitfall 1 / D-11). On `versionchange`, the tab cleanly unloads its DB connection via the page reload, letting tab B's upgrade proceed without blocking. |
| T-12-03-03 | Tampering (manually-edited IndexedDB row with non-array `tags`) | v6 `upgrade(tx => ...)` callback | mitigate | Inherited from Plan 02 — the `backfillTagsOnJob` helper uses `Array.isArray` (not `??=`), so tags values of `null`, strings, numbers, or objects are all normalized to `[]`. 5 unit-test cases prove this (Plan 02). |

No package installs in this plan — no supply-chain threat row needed.
