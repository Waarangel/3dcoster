<objective>
Close the v1.2 milestone's one blocker (PDF-04 lazy-load defeated by Rollup chunk ordering) and one warning (tax rounding divergence between PrintQuoteModal and CostCalculator) with three bounded, mechanical code edits, plus add a CI gate that catches this regression class on every future build.

Purpose: The audit-time integration check found that today's `vite.config.ts` `manualChunks` returns `'vendor'` for jspdf BEFORE the `/jspdf/` PDF check ever fires — because the `node_modules` outer block runs first. Result: jspdf ships in the vendor chunk, marketing pages static-import it, and the "lazy load only on Generate PDF click" promise (PDF-04) is silently broken for 100% of marketing-page visitors. Separately, `PrintQuoteModal.tsx:196` forks the tax math via inline `subtotal * (resolvedTax.rate / 100)`, producing sub-cent divergence from the canonical `calculateTax(sellingPrice, rate)` used in `CostCalculator.tsx:493` (`Math.round(price * rate) / 100`). Both fixes are mechanical and bounded — no behavior change for users, full architectural alignment.

Output: vite.config.ts with reordered manualChunks; a new `scripts/assert-no-static-pdf-import.mjs` build-output gate wired into `package.json`; `PrintQuoteModal.tsx` calling `calculateTax` instead of forking. The new gate proves the reorder worked and prevents future regressions of the same class.
</objective>
