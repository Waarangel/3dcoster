<objective>
Close v1.2-CODE-AUDIT #1 (CRITICAL — DESK-01) by reconciling the Tauri `fs:scope` capability with the unrestricted `save()` dialog so a desktop user can save a PDF anywhere the dialog allows (Desktop, Documents, Downloads, anywhere under `$HOME`) without `writeFile` throwing a scope-denied error. The fix combines (a) collapsing the bare `fs:allow-write-file` permission and the separate `{ fs:scope, $DOWNLOAD/* }` entry into a single per-permission inline-scoped entry `{ identifier: fs:allow-write-file, allow: [{ path: $HOME/**/* }] }` (Option C per 18-RESEARCH.md — narrows the broader scope to writeFile only, defense-in-depth against future `fs:allow-read-file` additions), and (b) wrapping the `writeFile` call site in `src/pdf/generateQuotePdf.ts` with a defensive try/catch that detects the `forbidden path: …` error string and re-throws an actionable message, so any future scope-narrowing regression surfaces a useful error instead of the generic "Could not generate quote."

Purpose: This is the first CRITICAL closure of v1.3. The audit's mechanistic claim may be partially absorbed by tauri-plugin-dialog's runtime `scope.allow_file()` auto-allow (see RESEARCH Summary), but DESK-01 demands a fix regardless — and the per-permission inline scope is the correct idiomatic Tauri 2 declaration that does not rely on undocumented plugin side-effects. The defensive try/catch is belt-and-braces: if Option C is the load-bearing piece (negative-control UAT-D will tell us), the user already gets a working save dialog; if a future capability edit re-narrows scope, the actionable error message remains. UAT-D is the load-bearing validation step that distinguishes "this fix closed a real bug" from "this fix preventively hardens a theoretical exposure" — either outcome closes DESK-01.
Output: Capability JSON updated, defensive try/catch + unit test landed, Cargo.lock refreshed by `npm run tauri build`, manual UAT (3 positive flows + 1 negative control) signed off by the developer. A 18-01-SUMMARY.md records the UAT outcomes including whether UAT-D actually surfaces the "forbidden path" error (which tells us whether the audit's bug was reproducible or theoretical).

```typescript
export async function generateQuotePdf(quote: Quote): Promise<void> {
  const doc = _buildDoc(quote);
  const filename = buildFilename(quote);

  if (!__IS_TAURI__) {
    doc.save(filename);
    return;
  }

  const { save } = await import('@tauri-apps/plugin-dialog');
  const { writeFile } = await import('@tauri-apps/plugin-fs');

  const savePath = await save({
    defaultPath: filename,
    filters: [{ name: 'PDF', extensions: ['pdf'] }],
  });

  if (!savePath) return;

  const buffer = doc.output('arraybuffer');
  await writeFile(savePath, new Uint8Array(buffer));     // ← wrap THIS in try/catch
}
```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User's filesystem ↔ Tauri-bundled web app | The user can pick any path the OS save dialog allows; Tauri's capability ACL is the validation boundary that decides whether `writeFile` is permitted to that path. Broadening from `$DOWNLOAD/*` to `$HOME/**/*` expands the allowed write surface but stays within the user's own home directory (and Tauri 2's `require_literal_leading_dot: true` default excludes dotfile/dotfolder contents like `~/.ssh/*`). |
| `@tauri-apps/plugin-fs` (Rust) ↔ JS catch handler | The Rust side throws `Error("forbidden path: {pathbuf}")` on scope denial; the JS catch detects this exact substring and re-throws an actionable message. The boundary is the error format contract — if a future plugin version changes the error string, the catch silently degrades to passing the raw message through (defense in depth via the original `throw err`). |
| Capability JSON file at build time ↔ embedded ACL in shipped binary | The capability is baked into the bundled binary by `tauri-build`; runtime tampering requires binary modification (out of app-level control). Risk handled by the build-time schema validator and the UAT-D negative control. |
