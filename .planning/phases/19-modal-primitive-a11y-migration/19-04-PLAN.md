<!-- Modal primitive API (from plan 19-01) -->

```typescript
interface ModalProps {
  isOpen: boolean;
  onClose: () => void;
  title: ReactNode;
  children: ReactNode;
  size?: 'sm' | 'md' | 'lg' | 'xl';  // default 'md'
}
// Size map: sm→max-w-sm, md→max-w-md, lg→max-w-lg, xl→max-w-3xl
// Modal auto-renders: <h3 id={titleId}>{title}</h3> + X close button with aria-label="Close"
// Modal auto-handles: Escape, backdrop mousedown, focus trap, focus restoration, body scroll-lock, portal
```

Import: `import { Modal } from './ui';` (or `from './ui/Modal'` if barrel is incomplete).

<!-- Primitives that now auto-id (from plan 19-02) -->

`Input`, `Textarea`, `Select` accept `id?: string`. When omitted, internally generated via `useId()`. Consumer pattern for label pairing:

```tsx
const nameId = useId();  // generated in consumer
<label htmlFor={nameId}>Name</label>
<Input id={nameId} value={name} onChange={...} />
```

OR (alternative — let primitive generate, but consumer doesn't get the id to use in htmlFor):
The recommended pattern (D-12) is consumer-managed `useId()` for explicit pairing.
