# Phase 22.1: Break-even formula reconciliation - Context

**Gathered:** 2026-05-27
**Status:** Ready for planning

<domain>
## Phase Boundary

Two break-even formulas in the codebase compute different numbers for the same user-saved job, producing a silent contradiction the user noticed during Phase 22 UAT:

- **CostCalculator** ([CostCalculator.tsx:459-478](../../../src/components/CostCalculator.tsx)) displays "Break-even Units" using `(modelCost + printerDepreciation + nozzleWear) / theoreticalProfitPerUnit`. Includes all fixed costs.
- **JobsManager pill** ([JobsManager.tsx:45-78](../../../src/components/JobsManager.tsx)) displays per-job break-even progress using `modelCost / effectiveProfitPerUnit`. Counts only model cost; depreciation+nozzleWear are not in the formula.

Phase 22.1 converges them on the **Calculator's broader formula** (Calculator wins — that's the user's mental model when setting Financial Targets) by:

1. Persisting a `fixedCostsAtSave` snapshot on `PrintJob` at save time
2. Switching `computeBreakEvenInfo` in JobsManager to the broader formula
3. Shipping a one-time reconcile helper to backfill the snapshot on every legacy IndexedDB job
4. Folding in two non-blocking warnings from Phase 22's code review (WR-01, WR-02) since they touch the same surface (`RecordSaleModal`)

**Out of scope (defer to other phases):**
- Calculator widget UI changes (no copy/layout changes — only the underlying displayed number stays the same, since Calculator's formula was already correct)
- Sales-revenue-aware break-even adjustments (`effectiveProfitPerUnit` logic in JobsManager stays as-is; only the numerator changes)
- Printer hourly rate / packaging amortization as additional fixed-cost categories (future phase if needed; `fixedCostsAtSave` nested-object shape leaves room)
- v9 Dexie migration (success criteria explicitly forbid a schema bump; D-18 schema-extension pattern from Phase 14 is the model)

</domain>

<decisions>
## Implementation Decisions

### Formula

- **D-01:** Calculator's formula wins. JobsManager's `computeBreakEvenInfo` ([JobsManager.tsx:45-78](../../../src/components/JobsManager.tsx)) widens to use the same fixed-cost denominator as the Calculator: `modelCost + depreciationAtSave + nozzleWearAtSave`. The `effectiveProfitPerUnit` logic (theoretical vs actual based on `copiesSold > 0`) stays — that's a feature, not the divergence we're fixing.

### PrintJob Schema

- **D-02:** Nested-object shape. PrintJob gains `fixedCostsAtSave?: { depreciation: number; nozzleWear: number }`. Optional, non-indexed — Dexie schema string unchanged (D-18 schema-extension pattern from Phase 14). Future-proof for extra fixed-cost categories (printer hourly rate, packaging amortization) without needing another schema migration.
- **D-03:** Both `CostCalculator.tsx` save paths ([:589](../../../src/components/CostCalculator.tsx) Update and [:625](../../../src/components/CostCalculator.tsx) Create) write `fixedCostsAtSave: { depreciation: costs.printerDepreciation, nozzleWear: costs.nozzleWear }` derived from the existing `fixedCosts` memo at [CostCalculator.tsx:445-455](../../../src/components/CostCalculator.tsx). No new compute path needed — the values are already in scope.

### Edit-time Policy

- **D-04:** Preserve saved snapshot until next Save. When a user opens a job for Edit, the Calculator form recomputes live depreciation+nozzleWear from current printer settings (existing behavior — drives the displayed widget numbers). The job's `fixedCostsAtSave` snapshot is NOT touched until the user clicks Save. Matches today's `costPerUnit` behavior (jobs are immutable snapshots until re-saved). Avoids hiding data drift behind silent recomputes.

### Reconcile Helper

- **D-05:** Helper lives at [src/db/backfill.ts](../../../src/db/backfill.ts) as a pure function `reconcileFixedCostsAtSave(jobs, printerInstances): PrintJob[]`. No Dexie deps. Returns updated job objects for the caller to `db.jobs.bulkPut`. Mirrors `backfillQuotesFromJobs` (Phase 16 D-17) and `reconcileQuoteCurrency` (Phase 20 DATA-03) — the canonical patterns already in this file.
- **D-06:** Backfill computes `depreciation` and `nozzleWear` from the same arithmetic the Calculator uses today: `printerInstance.depreciationPerHour * job.printTimeHours * (1 + job.failureRate)` and the analogous nozzle-wear formula (researcher confirms exact formula in [CostCalculator.tsx](../../../src/components/CostCalculator.tsx)). Jobs that already have `fixedCostsAtSave` defined are left alone (idempotent on the job level).

### Missing-Printer Edge Case

- **D-07:** When a legacy job's `printerInstanceId` references a deleted printer, snapshot to `{ depreciation: 0, nozzleWear: 0 }` and `console.warn` the orphan with the job id + name. The reconcile flag still flips to `done` (idempotent — orphan jobs are reconciled, just with zero-valued snapshots). Result: orphan jobs behave like today's pill (break-even on modelCost only — no surprise to the user). Surfacing the warning in the console lets power users clean up if they care; no UI prompt because that's UX work outside a hardening phase.

### Reconcile Trigger

- **D-08:** Once on app startup behind a Dexie meta-row flag. Add a `meta` table row with key `phase22_1_breakEvenReconcileV1` and value `done` after first successful reconcile. Mirrors the existing reconcile-on-startup gating used in [src/db/backfill.ts](../../../src/db/backfill.ts) (look for `reconcileCopiesSoldFromSales` invocation site — researcher confirms the exact wire-up path in `App.tsx` or `useDatabase.ts`). Idempotent, predictable, runs once per device. The reconcile helper itself remains pure — the gating lives at the invocation site.

### Code Review Carry-overs from Phase 22

- **D-09:** WR-02 fix — `RecordSaleModal` hydration `useEffect` ([RecordSaleModal.tsx:107-113](../../../src/components/RecordSaleModal.tsx)) drops `job.sellingPrice` from its dep array. A Pitfall 3 comment explains: a concurrent `useLiveQuery` emission that updates the job's selling price while the modal is open should NOT clobber the user's in-progress EDIT/CONVERT form state. Only `editingSale?.id` and `convertingFromQuote?.id` should drive re-hydration.
- **D-10:** WR-01 fix — `userProfile` prop removed from `RecordSaleModalProps` ([RecordSaleModal.tsx](../../../src/components/RecordSaleModal.tsx)) and from the call site in [JobsManager.tsx](../../../src/components/JobsManager.tsx). Confirmed dead by the Phase 22 code reviewer (declared in interface, passed by parent, never destructured/read inside the component).

### Test Coverage

- **D-11:** Three new tests required:
  - Unit test for `reconcileFixedCostsAtSave` (pure helper): coverage of (a) job with snapshot already set → unchanged, (b) legacy job + live printer → correct snapshot, (c) legacy job + missing printer → zero snapshot + warning logged, (d) idempotency (running twice produces same output).
  - Round-trip test: save a job through CostCalculator's Save handler → run reconcile (no-op for newly-saved jobs) → render the JobsManager pill → assert Calculator's "Break-even Units" displayed number === JobsManager pill's `breakEvenCopies` for the same job.
  - WR-02 regression test: render `RecordSaleModal` with editingSale set, simulate a `useLiveQuery` emission that mutates `job.sellingPrice`, assert form state for `salePrice` is unchanged.
- **D-12:** Tests live alongside their source files. Use raw `createRoot` + `act` per project convention (no `@testing-library/react`).

### Claude's Discretion

- Exact location of the reconcile invocation site (`App.tsx` startup useEffect vs `useDatabase.ts` initialization useLiveQuery) — researcher to identify and follow the `reconcileCopiesSoldFromSales` precedent.
- Whether to gate the reconcile behind app version (lock to v1.3+ users only) or run it for everyone — researcher to confirm via [src/db/backfill.ts](../../../src/db/backfill.ts) pattern; the file's existing reconcile entries all run unconditionally on startup.
- Test file naming: `backfill.test.ts` (extend existing) vs `backfill.fixedCostsAtSave.test.ts` (new file). Planner to decide based on existing test-file size.

</decisions>
