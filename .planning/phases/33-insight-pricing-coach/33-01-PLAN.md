<objective>
Add a cost-allocation visualization to the existing **Cost Breakdown** section of the
calculator: a slim stacked horizontal bar plus a legend showing each cost component's
**% share** of the total job cost. This is the smallest, safest sub-feature of Phase 33
and ships first.

go" picture — the trust/insight wedge vs SlicePrice3D. This is **pure render of values
that already exist** (`costs`, `fixedCosts`, shipping/packaging). NO new cost math.

Breakdown section, with a clean degrade-to-nothing path at total = 0.

  <files>src/utils/costAllocation.ts, src/utils/costAllocation.test.ts</files>
  <behavior>
    - buildCostAllocation(input) returns an ordered AllocationSegment[] where each segment
      is { key, label, value, pct, color }; segments with value <= 0 are omitted.
    - pct = value / total * 100, where total = Σ of included segment values.
    - Test: a job with filament=6, labor=3, electricity=1 → pcts 60/30/10, sum === 100.
    - Test: rounding — when raw pcts don't sum to exactly 100 (e.g. three equal thirds),
      the returned pcts still sum to 100 within the rounding tolerance the renderer uses
      (assert Σ rounded pct === 100, using the same largest-remainder/normalization the
      util applies — decide and lock it in the util, do not leave it to the bar widths).
    - Test (0-GUARD, SC1): total = 0 (all components 0 / empty form) → returns []
      (empty array), NEVER a NaN/Infinity pct. Renderer keys "no bar" off `[].length === 0`.
    - Test: a single non-zero component → one segment at 100%.
    - Test: negative/NaN inputs are treated as 0 (defensive — Number.isFinite guard),
      never propagated into pct.
  </behavior>
  <action>
    Create `src/utils/costAllocation.ts` as a pure, React-free, IO-free module mirroring the
    style of `src/utils/costCalc.ts` and `src/utils/salesReportAggregates.ts`. Export:

      - `COST_ALLOCATION_COLORS`: a stable, ordered color map keyed by component key, using
        Tailwind palette hues that fit the slate dark theme (e.g. filament=blue, labor=violet,
        electricity=amber, postProcessing=teal, shipping=cyan, packaging=sky, depreciation=slate,
        nozzleWear=rose, modelCost=fuchsia). Use concrete hex/`bg-*` tokens consistent with
        existing usage so the bar and legend share one source of truth.
