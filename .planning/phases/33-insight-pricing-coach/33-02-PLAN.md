<sc4_reconcile_note>
SC4 requires backup/restore inclusion AND a one-time reconcile per the project's
"reconcile legacy data" rule. The reconcile here is INTRINSIC, not a data migration:
  - The new fields are OPTIONAL numbers that default to UNSET. They derive nothing and
    have no legacy-derived value to repair, so there is no forward-only-fix risk.
  - Existing/older backups have no `targetHourlyRate` key; on restore the JSON simply
    lacks it and `userProfile.targetHourlyRate` reads as `undefined` → gauge treats it as
    "no target set" (renders the value with a neutral, non-judging state). This is the
    correct, lossless behavior — NOT a bug to migrate.
  - DO NOT introduce a one-time backfill that writes a fabricated target (that would be an
    "arbitrary number" — forbidden). "No target set" is the honest absence-of-data state.
  Verify the round-trip explicitly in the backup test (Task 3) so SC4 is provable.
</sc4_reconcile_note>
