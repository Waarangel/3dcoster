<decisions_to_confirm>
<!-- SPEC Open Question #1 — exact healthy-margin bands. Surface to the user; do NOT silently lock copy. -->
**OPEN QUESTION (exact margin bands).** SPEC's starting reference (SlicePrice3D + general
maker pricing): Direct-to-customer 65–85%, Wholesale 30–50%, Consignment 50–70%.
RECOMMENDATION: because **channel awareness is explicitly out of scope for this phase**
(coach is margin-driven only), DO NOT encode three overlapping per-channel ranges yet — that
implies a channel the coach can't know. Instead propose a single, non-overlapping ladder of
GENERIC health bands the executor can implement and the user can confirm/edit the copy on:
  - margin < 0%        → 'loss'        ("⚠ You're selling below cost — every sale loses money.")
  - 0% ≤ margin < 25%  → 'thin'        ("⚠ {m}% — very thin; no room to discount or absorb a refund.")
  - 25% ≤ margin < 50% → 'wholesale'   ("{m}% — solid wholesale-range margin.")
  - 50% ≤ margin < 65% → 'healthy'     ("{m}% — healthy retail margin with room to negotiate.")
  - margin ≥ 65%       → 'premium'     ("{m}% — premium margin; make sure the price still sells.")
These bands are NON-OVERLAPPING (the SPEC's per-channel reference ranges overlap, which can't
drive a single deterministic line). Confirm the exact thresholds AND the copy with the user /
domain expertise before locking. The util keeps thresholds as named constants so a copy/threshold
change is a one-line edit. When the later Channel Presets phase lands, this ladder becomes the
per-channel band source.
</decisions_to_confirm>
