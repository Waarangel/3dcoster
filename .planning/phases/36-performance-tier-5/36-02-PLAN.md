<objective>
Close PERF-11 (Audit 5.3) on `CostCalculator.tsx` — eliminate the pricing `useEffect`'s double-render-per-keystroke with a minimal, behavior-preserving dep-array trim.

The effect at lines 804-825 derives `sellingPrice`/`targetProfit`/`profitMarginPercent` from `trueCost` based on `lastEdited`, but its dep array (line 825) ALSO includes three of the values it SETS (`profitMarginPercent`, `targetProfit`, `sellingPrice`). So firing the effect changes a dep, which fires the effect again — a cascading second render every keystroke (RESEARCH §PERF-11, source-verified). The fix (Option A, RESEARCH-recommended over the event-handler Option B): trim the dep array to `[trueCost, lastEdited]` with a required `// eslint-disable-next-line react-hooks/exhaustive-deps` carrying an inline PERF-11 rationale. The effect body (the `trueCost <= 0` guard + all three branches) is untouched.

Purpose: Keep the Calculator responsive while typing. Hard constraint: ZERO behavioral change — the same derived price/profit/margin, and the `editingJob` rebase path (seeds `lastEdited='price'`, re-derives against current `trueCost`) must be preserved.
Output: `CostCalculator.tsx` with the trimmed dep array + comment; source-contract tests in `CostCalculator.test.tsx`.
</objective>
