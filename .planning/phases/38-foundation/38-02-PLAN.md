<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL query param → app state | The `?tab=` value is user-controllable (typed, bookmarked, or pasted). It crosses into app rendering logic and MUST be validated against a known whitelist before use. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-38-03 | Tampering | `?tab=` query param (untrusted URL input) | mitigate | Validate `rawTab` against `VALID_TABS.includes()` before ever using it to select a tab; any non-whitelisted value falls back to calculator AND is stripped from the URL via `setSearchParams({}, {replace:true})` (D-07). No `?tab=` value ever reaches conditional rendering without passing the whitelist. |
| T-38-04 | Information Disclosure | Bookmarkable/shareable tab URLs | accept | Only the active tab name (one of six public UI section labels) is in the URL — no IDs, no PII, no record references. Deep-links to sub-state (e.g. a specific open job) are explicitly out of scope this phase (D deferred). |
| T-38-05 | Denial of Service | Malformed/oversized `?tab=` value causing a render loop | mitigate | The D-07 effect replaces the param exactly once (keyed on `[rawTab, setSearchParams]`); after replace, `rawTab` becomes null and the effect no-ops — no loop. Whitelist check is O(6) membership, no ReDoS surface (no regex on the param). |
| T-38-SC | Tampering | npm installs | accept | Zero packages installed — `useSearchParams` ships with the already-present `react-router-dom@7.17.0`. No package-legitimacy checkpoint needed. |
</threat_model>
