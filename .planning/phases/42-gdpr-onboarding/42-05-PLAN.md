<objective>
Close the diagnosed major gap in the ONBD-01 onboarding wizard: the step-0 printer quick-add tile unmounts the wizard instead of advancing to the filament step, and `onboardingStep` is never persisted — so steps 2-3 are unreachable and a reload never resumes.

Root cause (confirmed, see debug session): `shouldShow` (useOnboarding.ts:44) and the auto-advance effect (OnboardingOverlay.tsx:59-64) both key off the same `instances.length` 0→1 transition on the same render. When the tile's fire-and-forget `addInstance` commits, `instances.length` flips to 1 while `onboardingStep` is still 0, so `shouldShow` recomputes to false and the effect's `!shouldShow` guard short-circuits before `advanceStep(1)` can run. Nothing persists; the overlay renders null forever. Mocked unit tests hid the race because they never exercise a live-updating `instances.length` against a not-yet-updated `step`.

Fix direction (the gap's primary recommendation): make the step-0 tile's onClick await `addInstance` and then call `advanceStep(1)` directly — mirroring the non-racy step-1 filament tile pattern — so the advance no longer depends on the racy effect. Prove it with a non-mocked real-Dexie integration test written RED-first.

Purpose: Restore a working, resumable first-run wizard for new users without regressing auto-skip (D-09) for users who already own a printer.
Output: A real-Dexie regression test (RED → GREEN); a deterministic step-0 tile advance; updated mocked unit assertions.
</objective>
