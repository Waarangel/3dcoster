    1. `create extension if not exists pgcrypto` (for gen_random_uuid / gen_random_bytes).
    2. `create table public.hosted_quotes` with columns: `token uuid primary key default gen_random_uuid()`, `owner_id uuid not null references auth.users(id) on delete cascade`, `snapshot jsonb not null`, `customer_first_name text`, `status text not null default 'published' check (status in ('published','unpublished'))`, `decision text check (decision in ('approved','declined'))`, `decision_note text`, `decided_at timestamptz`, `expires_at timestamptz`, `created_at timestamptz not null default now()`. Store ONLY the customer first name (D-08) — never the full customerSnapshot.
    3. `create table public.entitlements` with columns: `user_id uuid primary key references auth.users(id) on delete cascade`, `plan text`, `status text`, `current_period_end timestamptz`, `updated_at timestamptz not null default now()`. This table is written ONLY by the Paddle webhook (service role) in plan 43-06.
    4. `alter table public.hosted_quotes enable row level security;` and `alter table public.entitlements enable row level security;`.
    5. `revoke select, insert, update, delete on public.hosted_quotes from anon;` and `revoke select on public.entitlements from anon;`. Anon gets ZERO direct table access — do NOT create any permissive anon SELECT policy of any kind.
    6. Owner-only policies on hosted_quotes for the `authenticated` role: SELECT/INSERT/UPDATE/DELETE each scoped with `owner_id = (select auth.uid())`. Entitlements: an `authenticated` SELECT policy scoped `user_id = (select auth.uid())` and NO client write policy.
    7. `create function public.get_hosted_quote(p_token uuid) returns table(snapshot jsonb, customer_first_name text, status text, decision text, decided_at timestamptz, decision_note text, expires_at timestamptz) language plpgsql security definer set search_path = public` — body returns the single row `where token = p_token and status = 'published'`. It MUST NOT join or reference `entitlements` (D-11 lapse-safe: read visibility depends only on the row's own status/expires_at, never the owner's subscription). Zero rows for unpublished/expired/unknown → caller renders the D-16 branded 404.
    8. `create function public.approve_quote_decision(p_token uuid, p_decision text, p_note text) returns boolean language plpgsql security definer set search_path = public` — updates `decision`, `decision_note`, `decided_at = now()` `where token = p_token and status = 'published' and decision is null` and returns whether exactly one row changed. The `decision is null` guard enforces D-15 (one final transition) at the DB level so a replayed/forged second write is rejected regardless of UI. Validate `p_decision in ('approved','declined')` and reject otherwise.
    9. `revoke all on function public.get_hosted_quote(uuid) from public;` then `grant execute on function public.get_hosted_quote(uuid) to anon;` — same pattern for `approve_quote_decision(uuid, text, text)` granted to anon. These two RPCs are the ONLY anon-reachable data paths.
    10. A trigger function `public.notify_quote_decision()` and `create trigger hosted_quotes_decision_webhook after update of decision on public.hosted_quotes for each row when (old.decision is null and new.decision is not null) execute function public.notify_quote_decision();` — the trigger uses `net.http_post` (pg_net) to POST the new row id to `current_setting('app.settings.functions_url', true) || '/on-quote-decision'` (Supabase Edge Function URL convention `${SUPABASE_URL}/functions/v1/on-quote-decision`). The edge function is deployed in plan 43-06; until then this POST harmlessly 404s (email just does not send). Add a SQL comment noting the function is deployed in 43-06.

    Do NOT store customer email/address anywhere in this schema (D-08). Snapshot is the self-contained pricing payload only.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anonymous customer browser → Supabase PostgREST/RPC | Untrusted token-bearing reads/writes cross here; the whole non-enumerability guarantee lives at this boundary |
| authenticated maker (supabase-js) → hosted_quotes | Owner-scoped reads/writes; RLS owner policy is the control |
| Paddle webhook (service role) → entitlements | Only server-side, signature-verified writes (enforced in 43-06) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-43-01 | Information Disclosure | hosted_quotes RLS / PostgREST | critical | mitigate | Revoke anon SELECT entirely; expose reads only via `get_hosted_quote` SECURITY DEFINER RPC; NO permissive anon policy (Pitfall 1) |
| T-43-04 | Tampering | approve_quote_decision RPC | high | mitigate | Token-scoped capability write + `decision is null` DB guard so a second/forged decision write is rejected (D-15) |
| T-43-07 | Elevation of Privilege | get_hosted_quote / D-11 | medium | mitigate | Read RPC must NOT join entitlements — published-link visibility never depends on the owner's live subscription (Pitfall 5) |
| T-43-06 | Information Disclosure | /q/[token] guessing | low | accept | UUID v4 default (122 bits) via gen_random_uuid(); rate-limiting deferred to post-launch if abuse observed |
| T-43-SC | Tampering | supabase CLI / migration | low | mitigate | CLI is a global dev tool (not a package.json dep); no [ASSUMED]/[SUS] npm install in this plan |
</threat_model>
