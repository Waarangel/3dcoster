<objective>
Ship Pro subscription billing through Paddle as Merchant of Record (PRO-04, D-01): a client checkout for the EUR 6.90/mo and EUR 69/yr plans, a signature-verified webhook that syncs the Paddle subscription state into the Supabase `entitlements` table, a `BillingPanel` (subscribe / view status / cancel) mounted in the account area, and a `useEntitlement` hook the rest of the app reads. Price is anchored under 3DPrintQuote's EUR 9.90/mo (D-02).

Purpose: Webhooks are the billing source of truth; the app only ever READS the resulting entitlement row (Architectural Responsibility Map). Paddle handles VAT/tax remittance so a solo Canadian dev never files. The lapse-safe rule (D-11) means cancellation never yanks existing customer links — entitlement gates only new publishes (already enforced in 43-04).

Output: A working subscribe/cancel loop, server-authoritative entitlements, and Pro status in the app.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Paddle → /api/webhooks/paddle | Untrusted until the signature is verified; the only writer of entitlements |
| browser → Paddle checkout | Client token is public; API key/webhook secret never reach the browser |
| webhook → entitlements (service role) | Server-authoritative; bypasses RLS deliberately, so it must be tightly signature-gated |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-43-03 | Spoofing/Tampering | Paddle webhook | high | mitigate | Verify Paddle signature with PADDLE_WEBHOOK_SECRET before any write; invalid/unsigned -> 400 (Don't Hand-Roll: use Paddle's helper) |
| T-43-02 | Information Disclosure | VITE_ secret leak | high | mitigate | Only client token + price ids are VITE_-prefixed; API key/webhook secret/service role are server-only; grep guard |
| T-43-14 | Elevation of Privilege | client writing entitlements | high | mitigate | entitlements has no client write policy; only the service-role webhook writes; client reads own row only |
| T-43-07 | Elevation of Privilege | cancel yanking live links | medium | mitigate | Webhook never touches hosted_quotes; entitlement gates only new publish (43-04), D-11 lapse-safe |
| T-43-SC | Tampering | @paddle/paddle-js install | medium | mitigate | Research-mandated blocking-human checkpoint (no-repository package; confirm name vs Paddle docs) |
</threat_model>
