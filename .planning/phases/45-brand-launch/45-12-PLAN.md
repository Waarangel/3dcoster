<objective>
Close G-45-CURRENCY: marketing Pro pricing currently hardcodes EUR 6.90 for every
visitor. Add a currency-resolution + display-conversion layer so visitors see the
Pro price approximated in their home currency while the fixed EUR billing amount is
always disclosed. Billing truth (EUR 6.90/mo · EUR 69/yr in src/pricing.ts,
mirrored from BillingPanel.tsx) is unchanged — this is a display layer on top of it.

Resolution ladder (founder-confirmed during UAT): stored app currency preference
(the no-account "logged in" analog, in IndexedDB settings) → navigator.language
locale inference → USD fallback. Conversion rides the existing useFxRates /
convert() display-time seam. Never imply we charge in the displayed currency.

Purpose: a Pro price shown only in EUR reads as "not for me" to non-EU makers; a
disclosed home-currency approximation is legible without misrepresenting the charge.
Output: a pure pricingDisplay module + useDisplayPrice hook, wired into all three
marketing Pro-price surfaces, with the pricing guard test extended (not deleted).
</objective>

Interface notes for the executor (already verified in the codebase):
- `convert(amount, from, to, table): number | null` and `canConvert(...)` live in
  `src/utils/fxConvert.ts`. `convert` returns null (never a guessed number) when the
  table is missing or a currency is uncovered.
- `formatCurrency(amount, currency, locale?)` in `src/utils/currency.ts` renders the
  curated symbol + decimal places (EUR → 2dp, JPY → 0dp). `CURRENCY_CONFIG` there is
  the authoritative list of the 18 supported `Currency` codes, each with a `country`
  ISO field.
- `useFxRates(): FxRateTable | null` in `src/hooks/useFxRates.ts` supplies the cached
  USD-based table (reads IndexedDB; null until first table loads).
- Stored currency preference lives in the `userProfile` settings row. Read it WITHOUT
  the CAD default: `getSetting<UserProfile | null>(settingsKeys.userProfile, null,
  isUserProfile)` — all three (`getSetting`, `settingsKeys`, `isUserProfile`) are
  exported from `src/db/database.ts`; `UserProfile` type from `src/types.ts`. A null
  return means "no stored preference" and MUST fall through to locale inference.
- `Currency` union (18 codes) is in `src/types.ts`.

    - REGION_TO_CURRENCY: maps ISO 3166 region codes to a supported Currency. Direct
      matches from CURRENCY_CONFIG country fields (US→USD, GB→GBP, CA→CAD, AU→AUD,
      NZ→NZD, CH→CHF, SE→SEK, NO→NOK, DK→DKK, PL→PLN, CZ→CZK, JP→JPY, CN→CNY, IN→INR,
      BR→BRL, MX→MXN, ZA→ZAR) PLUS eurozone members to EUR (DE, FR, ES, IT, NL, IE, PT,

    - regionFromLanguageTag(tag?): string | undefined — try `new Intl.Locale(tag).maximize().region`;
      fall back to a defensive split on '-' picking a 2-letter uppercase region subtag;
      undefined when nothing resolves (including tag undefined).
    - resolveDisplayCurrency(stored: Currency | null, languageTag: string | undefined): Currency
      — returns `stored` when non-null; else REGION_TO_CURRENCY[region] when resolvable;
      else 'USD'.
    - formatApproxPrice(billingAmount: number, billingCurrency: Currency, displayCurrency:
      Currency, table: FxRateTable | null): string | null — returns null when
      displayCurrency === billingCurrency OR convert() returns null; otherwise
      formatCurrency(convert(billingAmount, billingCurrency, displayCurrency, table)!,
      displayCurrency). The approx is ALWAYS the secondary value; callers pair it with
      the verbatim billing label (never call this without also rendering billing).

    - unknown/absent: stored null + tag 'xx' → 'USD'; stored null + tag undefined → 'USD'.
    - formatApproxPrice returns null when displayCurrency === billingCurrency.
    - formatApproxPrice returns null when table is null (no guessed number).
    - formatApproxPrice returns a formatted string in the display currency when a table
      covers both currencies (e.g. EUR→USD with a seeded table yields a '$…' string).
