<objective>
Deliver the white-label hosted quote page (the public page, D-12): swap in the maker logo + business name and drop 3DCoster marks, keeping the current dark design. Two deliberate rules distinct from the PDF: the logo BAKES into the frozen publish snapshot at publish time (D-11 — already-live links never change), and the "Powered by 3DCoster" footer stays UNTIL a logo is actually set (D-09 — passive publishers keep carrying attribution; this is DIFFERENT from the PDF's D-05 "any Pro user loses the footer", per D-10 — do NOT align them). The logo data URL is interpolated into server-rendered HTML, which makes strict data-URL allowlisting the load-bearing XSS control (Pitfall 4) — validated at BOTH publish-write time (client) and render time (server). `api/` cannot import from `src/`, so the server validator is a lockstep copy of the canonical `src/utils/logoDataUrl.ts` regex.

Purpose: The hosted page is the public face of a maker's brand; getting the footer rule (D-09) and the XSS allowlist right is the whole point.
Output: Logo joins the publish payload (validated), a mirrored server validator, hosted-page logo render + conditional footer, and the first-ever test file for `api/q/[token].ts` (Wave-0 gap).

Decision coverage: D-05 (publish is entitlement-gated via the existing hasActiveEntitlement — unchanged), D-09 (powered-by until logo set), D-10 (hosted differs from PDF — do not align), D-11 (frozen snapshot; republish to change), D-12 (design unchanged minus 3DCoster marks).
