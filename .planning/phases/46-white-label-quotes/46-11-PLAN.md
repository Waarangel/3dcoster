<objective>
Close gap G-46-6R: after publishing a quote, the hosted-quote link must stay
retrievable — copyable on demand and findable again later from the quote row —
not only visible for ~5s in an auto-dismissing toast.

The data layer is already correct: usePublishedQuote.ts:160-168 durably writes
`publishedUrl` (`https://3dcoster.com/q/<token>`) and `hostedToken` onto the
local Quote. The defect is purely in the UI: NO component ever reads
`quote.publishedUrl` back (repo-wide, its only references are the type
declaration at types.ts:428 and the hook that writes it). A published quote
renders only an inert "Live link" text badge (JobsManager.tsx:317-321) and an
"Unpublish"-only button (ShareQuoteButton.tsx:116). The sole link surfaces are a
one-shot clipboard write and a 5s toast — and on desktop the
`navigator.clipboard?.writeText(url)` optional-chain resolves without throwing
when the WebView exposes no clipboard, so the toast FALSELY claims "link copied".
Republishing is not a workaround: it mints a new token (D-13) and 404s the URL
the customer already holds.

The fix adds the missing read sites: a reusable Copy-link + Open-hosted-page
affordance rendered wherever a quote is published, plus a truthful clipboard
helper so "copied" is only ever claimed when the copy actually happened.

Purpose: a Pro user (web or desktop) can always recover the exact hosted link
they already sent — no republish, no reliance on a vanishing toast.
Output: a `copyToClipboard` util, a `HostedLinkActions` component (Copy + Open),
two new icons, an honest publish toast, and the affordance mounted on both
persistent published-quote surfaces.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User click -> clipboard write | Client-only, no network. Writes the already-shareable hosted URL to the OS clipboard. |
| User click -> open external URL | Opens the hosted quote in the system browser (desktop, via plugin-shell) or a new tab (web). The URL is always the internally-constructed `quote.publishedUrl`, never user-typed. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-46-11-01 | Information Disclosure | HostedLinkActions copy — hosted URL to OS clipboard | low | accept | The URL is a non-enumerable token link (PRO-03) that the maker created expressly to share with their customer; putting it on the clipboard is the intended action. No new data leaves the device (clipboard is local). Identical risk surface to the shipped post-publish clipboard write. |
| T-46-11-02 | Tampering | HostedLinkActions open — external URL launch | low | mitigate | Only `quote.publishedUrl` (internally built `https://3dcoster.com/q/<token>`, never user input) is ever passed to open(). Web path uses `window.open(url, '_blank', 'noopener,noreferrer')`; desktop reuses the already-granted `shell:default`/allow-open capability via the proven UpdateBanner plugin-shell pattern. No arbitrary/user-controlled string reaches the shell. |
| T-46-11-03 | Spoofing | Publish toast false "copied" claim | low | mitigate | copyToClipboard returns a truthful boolean; the toast claims "copied" only when the write actually resolved, removing the desktop optional-chain false positive the gap reported. |
| T-46-11-SC | Tampering | npm/cargo installs | n/a | mitigate | ZERO new packages: `@tauri-apps/plugin-shell` is already a dependency and no clipboard Rust plugin is added, so no package-legitimacy gate is required. |
</threat_model>
