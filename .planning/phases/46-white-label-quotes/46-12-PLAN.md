Close UAT gap G-46-18: opening a published hosted-quote link lands on a blank page (React Router logs `No routes matched location "/q/{token}"`).

The diagnosis (`.planning/debug/hosted-link-open-blank-page.md`) found TWO defects behind the single symptom, plus one verification that cannot run pre-launch:

1. LATENT PRODUCTION BUG — `vercel.json` only EXCLUDES `q/` from the SPA rewrite but never MAPS `/q/:token` to the serverless function. `api/q/[token].ts` answers only at `/api/q/{token}`, so after the v2.0 deploy `GET /q/{token}` would hit a Vercel platform 404. Fix: add the `/q/:token → /api/q/:token` rewrite.
2. SECONDARY (the user's explicit ask) — the web (`!__IS_TAURI__`) branch of `src/main.tsx` has no `path="*"` catch-all, so any unmatched location renders `null` (blank page). Fix: a lazy, themed NotFound page wired inside `MarketingLayout`.
3. DEFERRED VERIFICATION — the /q rewrite preview-deploy check (200 for a published token; byte-identical branded 404 + noindex/no-store otherwise) needs a real Vercel preview deploy. Production stays pre-v2.0 until the founder pushes (deploy guard: DEPLOY_OK=1). Record it as a launch-day checklist item — do NOT deploy.

Purpose: A Pro user's published link must resolve to the hosted quote page for their customer; when a URL genuinely cannot be served, the user sees a friendly message, never a blank page.
