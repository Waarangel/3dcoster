<objective>
The Supabase backend for zero-knowledge cloud sync: one `sync_blobs` table (one ciphertext row per account, base64 TEXT not bytea), owner-only RLS mirroring `entitlements`/`hosted_quotes`, a `version` compare-and-swap RPC (`upload_sync_blob`) that closes the cross-device lost-update race, Realtime Authorization RLS for the private `sync:<uid>` notify channel, a `pg_cron` 90-day retention job, and a service-role `delete-account` edge function for D-14 level-2 deletion. <threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anon → Supabase REST/RPC | Untrusted public callers must reach zero sync data |
| device A ⇄ device B → shared sync_blobs row | Two physical devices race a shared remote resource |
| non-owner → realtime sync:<uid> channel | Only the owning account may publish/subscribe |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-47-03 | Information Disclosure | sync_blobs anon access | high | mitigate | `revoke ... from anon`, owner-only RLS, no permissive anon policy; enumerability regression test (mirrors T-43-01) |
| T-47-04 | Tampering (lost update) | concurrent cross-device write | high | mitigate | CAS `update ... where version = p_expected_version` + client retry (47-04); a stale/replayed write fails the same clause |
| T-47-05 | Spoofing | realtime broadcast forgery | medium | mitigate | private channel + `realtime.messages` RLS scoped to `auth.uid()` |
| T-47-06 | Denial of (privacy) Service | retention cron never runs | medium | mitigate | server-side `pg_cron` job (not client cleanup-on-access); auditable schedule matching the privacy promise |
| T-47-07 | Elevation of Privilege | delete-account service role misuse | high | mitigate | edge function verifies caller JWT → deletes only that uid; service-role key never leaves the function |
</threat_model>
