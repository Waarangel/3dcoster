# Phase 47.1 Plan 01: One-off post-processing cost, tracer slice Summary

**A user can add a named one-off post-processing cost (the founder's $200 auger) with no library asset; it flows through the Cost Breakdown and pricing reducer and saves on the job, charged flat (not scaled by the failure rate), with tested sanitizer/normalizer helpers ready for 47.1-02.**

## Accomplishments

- `ManualCostLine` type plus optional `PrintJob.manualMaterials` / `manualPackaging` (Dexie schema string unchanged, DB stays at v13, no migration).
- `calculateManualLinesCost` guards non-arrays, non-finite, zero and negative costs and rounds each cost to cents. `calculateCost` adds the one-off total to `materials` and `subtotal`, and to `failureAdjusted` outside the multiplier (D-07). With no lines, every value is the original expression plus 0, so the outputEquivalence snapshot is untouched.
- `useCostDerivedValues` passes `manualMaterials` to BOTH `calculateCost` calls and both dependency arrays (Pitfall 1). `useCostForm` holds the state, persists it in the draft blob, restores it unconditionally on edit, and resets it in `clearForm`.
- Post-Processing Materials card: "+ One-off cost" button (secondary, never disabled) with an InfoTooltip explaining the flat charge, one-off rows keyed by `line.id` with name input, compact cost input, and a labelled `RemoveButton`.
- Save writes `manualMaterials` (undefined when empty) and `costPerUnit: trueCost` includes the line exactly once.
- Task 2 (TDD): `sanitizeManualLines` and `normalizeManualLinesForSave` with 24 unit tests including hostile-key and immutability cases.
