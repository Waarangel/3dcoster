## Cross-Phase Integration Findings

### 🔴 BLOCKER — PDF lazy-load defeated by Rollup circular chunk

- **Affected REQ-IDs:** PDF-04 ("jspdf must be lazy-loaded; bundle stays ≤ 300 KB gz")
- **Files:** `vite.config.ts` (manualChunks) + 6 dist/assets/*-Page.js chunks
- **Evidence:** `import"./pdf-Ckwo6cOQ.js"` appears as a STATIC (not dynamic `import()`) statement in all 6 marketing page chunks: FeedbackPage, ChangelogPage, FAQPage, FeaturesPage, LandingPage, DownloadPage. Rollup emits a `Circular chunk: vendor -> react-vendor -> vendor` warning at build time. The `assert-no-pdf-preload.mjs` gate only scans `dist/index.html` for `<link rel="modulepreload">` and does NOT catch static imports injected into lazy-loaded route chunks.
- **Runtime impact:** Any user visiting Landing/FAQ/Features/Changelog/Feedback/Download fetches the 77.79 KB gz PDF chunk eagerly, before any PDF interaction. The marketing pages should not pay the PDF cost.
- **What passes:** `assert-bundle-size.mjs` (main chunk 62 KB gz, well under 300 KB). `assert-no-pdf-preload.mjs` (no modulepreload tag). PDF-05's main-chunk gate is unaffected.
- **What fails:** PDF-04's lazy-load INTENT.
- **Remediation:**
  1. Resolve the circular vendor chunk dependency in `vite.config.ts`'s `manualChunks` — likely by ensuring `jspdf`/`jspdf-autotable` are NOT pulled into the `vendor → react-vendor` cycle (return a guard before the `node_modules` catch-all, or refine which packages go to which chunk).
  2. Tighten `scripts/assert-no-pdf-preload.mjs` to scan ALL `dist/assets/*.js` files for static `import"*pdf*"` patterns, not just `dist/index.html` modulepreload tags.
  3. Rebuild and verify only `dist/assets/index-*.js` references the pdf chunk via dynamic `import()`.

### 🟡 WARNING — Tax amount rounding divergence between CostCalculator and PrintQuoteModal

- **Affected REQ-IDs:** TAX-02, PDF-02 (data-contract consistency)
- **Files:** `src/components/PrintQuoteModal.tsx:196` vs `src/utils/costCalc.ts:136` (`calculateTax`)
- **Evidence:** CostCalculator uses `calculateTax`'s `Math.round(price * rate) / 100`; PrintQuoteModal computes `subtotal * (resolvedTax.rate / 100)` inline without rounding. For `sellingPrice=29.99, rate=13`: Calculator stores `taxAmount=3.90`, modal snapshots `taxAmount=3.8987`. PDF renders the modal's value.
- **Severity:** sub-cent divergence in nearly all cases; usually invisible after `formatCurrency` formatting. Not data-corruption, but the two surfaces should share one tax helper to honor the "same 3-layer resolution everywhere" contract.
- **Remediation:** In `PrintQuoteModal.tsx`, replace the inline expression with `calculateTax(subtotal, resolvedTax.rate).taxAmount` (import from `src/utils/costCalc.ts`).

### 🔵 NIT — New PrintJobs from CostCalculator create path have `tags: undefined` (not `tags: []`)

- **Affected REQ-IDs:** TAGS-01 (minor; spec D-02 says empty input → `tags: undefined` is correct)
- **File:** `src/components/CostCalculator.tsx` lines 607-634 (create path)
- **Evidence:** Update path writes `tags: editingJob.tags`; create path omits the `tags` field entirely. New jobs get `tags: undefined`. Migrated legacy v1.0/v1.1 jobs get `tags: []` (Phase 12 backfill). Both render identically (`(job.tags ?? [])` guards everywhere).
- **Severity:** documentation-grade; no functional impact. Could be tightened by writing `tags: undefined` explicitly in the create path for symmetry with the spec.
