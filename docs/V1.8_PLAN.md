## Feature A — Material inventory tracking (#20)

Free floor: **manual stock + deduct-on-job + on-screen low-stock flag.** (Pro later: push/email
alerts, auto-reorder, supplier sync, multi-location.)

### Key decision: a stock **ledger**, not a `currentStock` field
Recommended: an append-only **`stockEvents`** store `{id, assetId, delta, kind:'job'|'manual', refId, timestamp, note?}`.
`currentStock = SUM(delta)` per asset. Rationale: a flat field can't stay correct across job
**edit/delete** without fragile delta-math, and a ledger is exactly what a Pro alerts/reorder
service subscribes to (the additive seam). Mirrors how the codebase already keeps `sales` canonical
and derives `copiesSold`.

### Key decision: deduction trigger = job save, idempotent on `refId = jobId`
Deduct when a job is saved (`CostCalculator.handleSaveJob`), the one place with full material data.
Idempotency: within a Dexie tx, **delete prior events for that `jobId`, then insert fresh ones** →
- create: inserts deductions (one per `FilamentUsage` in grams, one per `MaterialUsage` in units);
- edit/re-save: old events replaced → no double-count;
- delete job: extend the existing `deleteJob` transaction to also delete `stockEvents WHERE refId = jobId`.

### Files
- **New:** `src/db/stockEvents.ts` (pure: `applyJobStockEvents`/`removeJobStockEvents`/`deriveCurrentStock`), `src/hooks/useStockEvents.ts` (`useLiveQuery` → `stockByAssetId` map + `logManualAdjustment`), `src/components/inventory/{StockBadge,StockEditor,LowStockBar}.tsx`, plus `.test` files.
- **Modify:** `src/types.ts` (add `StockEvent`; `lowStockThreshold?: number` on `Asset`), `src/db/database.ts` (**Dexie v11** new store `'id, assetId, refId, timestamp'`, no-op upgrade; extend `deleteJob` tx), **`src/utils/backupSchema.ts` (add `stockEvents` to `BACKUP_STORES` + `BackupData` + `DATE_FIELDS:['timestamp']`)** ← the silent-backup-drop gotcha, `src/hooks/useDatabase.ts`, `src/components/AssetLibrary.tsx` (StockBadge per material row + threshold field + LowStockBar header).

### Build order (TDD)
1. Types + v11 schema + backupSchema lockstep + `stockEvents.ts` pure helpers + **tests first** (idempotency, grams-vs-units, delete). Re-run backup tests.
2. `useStockEvents` hook + tests; extend `deleteJob` tx; backup round-trip test for the new store.
3. Wire `applyJobStockEvents` into `handleSaveJob` (after save resolves; errors logged, never block save).
4. UI: StockBadge/StockEditor/LowStockBar in AssetLibrary; threshold field.
5. Ship: features.ts + NewBadge, roadmap removal, CHANGELOG.

## Feature B — PDF sales report (#33)

Free floor: **generate + download a designed PDF (and CSV) for any date range.** A document for
tax records / loan apps — **NOT** a format toggle on the CSV export buttons. (Pro later: scheduled
auto-email, send-to-accountant, branded.)

### Key decision: `aggregate() → render()` as a hard module boundary
- **`src/utils/salesReportAggregates.ts`** — pure `computeSalesReport(sales, jobsById, range, currency, fxTable): SalesReportData` → totals, **revenue by marketplace**, fees, profit, optional by-month breakdown. Multi-currency via `convert()` with the **same null-contract** as `computeJobsAggregates` (missing FX → `null` cell + `hasPartialData` flag).
- **`src/pdf/generateSalesReportPdf.ts`** — lazy jsPDF render that consumes only `SalesReportData`; mirrors `generateQuotePdf.ts` (dynamic import + `__IS_TAURI__` save branch + `ensureFontsLoaded`). Must live in `src/pdf/` (CI gate `assert-no-static-pdf-import.mjs` keeps it off the main bundle).
The Pro scheduler/email/brand layer later wraps the *same* `computeSalesReport()` — zero refactor.

### Key decision: entry point = a **Reports section in Settings → Data tab** (not a 6th top-level tab)
The tab bar is already at 5; report generation is a periodic (monthly/annual) action, so it belongs
in the Data tab next to backup/export. New `ReportsSection` component owns a **Month / Year / Custom**
range picker + a **live preview** (computeSalesReport is synchronous/pure) + "Download PDF" / "Download CSV"
(CSV reuses `generateSalesExportCsv` from `jobsExport.ts`, range-filtered). No new Dexie store.

### Files
- **New:** `src/utils/salesReportAggregates.ts`(+test), `src/pdf/generateSalesReportPdf.ts`(+smoke test), `src/components/ReportsSection.tsx`(+test).
- **Modify:** `src/components/SettingsModal.tsx` (render ReportsSection in Data tab; +4 props), `src/App.tsx` (thread `allSales`/`allJobs`/`userCurrency`/`fxTable` — add `useAllSales()`), `src/features.ts`, `src/roadmap.ts`.

### Build order (TDD)
1. Aggregation: types + **tests first** (range filtering, FX null-propagation, marketplace/month grouping, boundary dates) → implement `computeSalesReport`.
2. PDF render: smoke test (`%PDF` bytes) → implement (mirror generateQuotePdf).
3. UI: ReportsSection (range picker + preview + triggers) + tests; wire into SettingsModal + App.
4. Ship: features.ts + NewBadge (absolute-positioned per badge rule), roadmap removal, CHANGELOG.

## Open decisions for the user (resolve before/while building)

**Inventory**
1. **First-run, no backfill** — existing jobs won't retro-deduct; instead show a one-time "Set your current stock levels" prompt in Asset Library. OK? *(recommended)*
2. **Deduct packaging materials too** (boxes/labels), not just filament + post-processing? *(recommended yes)*
3. **Filament stock unit** — show grams ("340 g remaining") with an optional "≈ 0.3 spools" if `unitsPerPackage` set? *(recommended)*
4. **Atomicity** — job-save and stock-event are two writes (not one tx), matching the existing `copiesSold` tolerance. Accept, or invest in an atomic job+event write? *(recommended: accept)*

**PDF report**
5. **Aggregate-only document** (totals + by-marketplace + by-month), with per-sale detail left to the CSV? *(recommended; per-sale rows = a Pro "detailed report")*
6. Reports **above or below** Backup/Restore in the Data tab? *(recommended above — routine vs. emergency)*

**Scope/sequencing**
7. Both in one **v1.8.0**, or ship inventory first (v1.8.0) and the report second (v1.8.1)? Bundling both is fine; they're independent and don't touch the same files.
